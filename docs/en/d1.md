# The MangoPi MQ-Pro (Allwinner D1) with Asmonite

The Allwinner D1 has one T-Head C906 core: RISC-V with 64 bits (RV64GC), 1 GHz. Asmonite assembles RV64 code
(`.arch riscv64`, `.target d1`), loads it over USB into the SRAM of the chip and debugs it, **with one USB cable,
without a debug probe, without JTAG, without sunxi-fel or xfel**: breakpoints, steps, the registers with 64 bits,
the memory. When the program returns with `ret`, Asmonite shows `a0` and `a1`.

Tested with a MangoPi MQ-Pro (D1, 1 GB).

## What you need

- A MangoPi MQ-Pro (or another board with the D1 or F133), **without an SD card**: the boot ROM of the D1 finds
  nothing to start and waits in its **FEL mode** for a host on USB.
- A USB-C cable at the port **OTG** of the board (not HOST). In the Device Manager the board shows as an unknown
  device with the id `USB\VID_1F3A&PID_EFE8`.
- Windows 10 or 11.

## Setting up once: the driver of the FEL mode

The FEL mode brings no driver. Windows has a suitable one, WinUSB:

1. Device Manager: right-click the unknown device, **Update driver**.
2. **Browse my computer for drivers**, then **Let me pick from a list of available drivers on my computer**.
3. **Universal Serial Bus devices**, Next.
4. Manufacturer **WinUsb Device**, model **WinUsb Device**, Next, and confirm the warning.

Then the device is called "WinUsb Device". **Debug > Debug targets > MangoPi MQ-Pro (Allwinner D1) > Test the
connection** should say "an Allwinner D1/F133 (SoC id 1859) in the FEL mode of its boot ROM".

## A program

```asm
.target d1
.arch riscv64
.imagebase 0x20000

_start:
    li   a0, 42
    ret
```

F9 (run) or F7 (step into) writes the program into the SRAM at `.imagebase` (`0x20000` to `0x277FF`, 30 KB),
reads it back and starts it at `_start`; F7 stops there. Then as on the other boards: F7 and F8 step line by line
(a line of several instructions, as `li` of a large number, is one step), F5 sets a breakpoint, F9 runs to the next
one, the registers `x0` to `x31` (by their names: `ra`, `sp`, `a0` ...) show all 64 bits, and the memory window reads
the memory of the chip. When `_start` returns with `ret`, the session ends and the output window shows

```
The program returned: a0 = 42 (0x2A), a1 = 0 (0x0)
```

and the board is ready for the next F9.

**No pause.** The program runs between two calls of the boot ROM, and FEL waits until it comes back: a running
program cannot be paused, and Stop lets it run on. Set a breakpoint before the program runs into a loop. A program
that never stops runs until the board is unplugged and plugged in again.

The program starts with `sp` at `0x27800` (its stack grows down from there) and `ra` at the end mark of the
debugger; it is called like a function: before `ret`, `sp` must be the one of the start. An exception (an illegal
instruction, a load from an address without memory) stops the program at the instruction, with its cause in the
output window.

How it works: a small stub of Asmonite at `0x27800` is called by the boot ROM (FEL EXEC). It keeps every register of
the boot ROM, loads the registers of the program and jumps to its pc; a breakpoint (`ebreak`) or an exception enters
the trap handler of the stub, which keeps the registers of the program and returns to the boot ROM. Then FEL answers
again, and Asmonite reads the registers and the memory over USB.

## RV64 in short

- The registers have 64 bits. `ld` and `sd` load and store 8 bytes, `lw` extends the sign of a word to 64 bits,
  `lwu` fills with zeros.
- The W instructions (`addw`, `addiw`, `sllw`, `mulw` …) compute with 32 bits and extend the sign of the result:
  the arithmetic of `int` in C.
- `li` takes any 64-bit number (up to 8 instructions); with a label it gives 4 instructions.
- F1 on an instruction shows its description; the instruction reference on the website lists the encodings.

## The examples

| File | What it does |
|---|---|
| `examples/d1/sum_ram.asm` | The sum of 1 to 100 in a loop: a0 = 5050 |
| `examples/d1/fibonacci_ram.asm` | The 90th Fibonacci number, 2880067194370816120: a number of 62 bits in one register |

## If something does not work

| Message | What to do |
|---|---|
| "No Allwinner chip in its FEL mode is plugged in" | Take out the SD card, use the port OTG, plug in again |
| "... Windows has no driver for it" | The driver as above (once) |
| "The D1 cannot be paused over FEL" | Unplug the board and plug it in again, then set a breakpoint first |
| "The board in its FEL mode is no D1" | Another Allwinner chip: not supported |

## Limits

- No pause of a running program (see above), no output of the program (its UART0 is on the pin header of the
  board and needs a USB serial adapter).
- Only the SRAM below `0x27800`; the DRAM (512 MB or 1 GB) needs its controller set up first.
- The vector instructions of the C906 (RVV 0.7.1) and the extensions of T-Head are not in the assembler.
- How the FEL mode is spoken to: the protocol of `sunxi-tools` (`fel_lib.c`).
