# x86-Befehle (i386)

Die Befehlsinfo von Dismonite (F1) zeigt den Abschnitt zum Befehl der aktuellen Zeile.
Jeder Abschnitt beginnt mit `## ` und den Namen, die er erklärt.

## mov – Wert kopieren

Kopiert die Quelle in das Ziel. Die Quelle bleibt unverändert.

**Syntax:** `mov ziel, quelle`

- Ziel: Register oder Speicher
- Quelle: Register, Speicher oder Zahl (Immediate)
- Nicht erlaubt: von Speicher zu Speicher; das geht nur über ein Register.

**Flags:** keine

```asm
mov eax, 5       ; eax = 5
mov ebx, eax     ; ebx = eax
mov [zahl], eax  ; schreiben
mov ecx, [zahl]  ; lesen
```

Eckige Klammern bedeuten „der Speicher an dieser Adresse“, ohne Klammern ist die Adresse selbst gemeint.

Verwandt: `lea`, `xchg`, `push`

## push – auf den Stack legen

Legt einen Wert oben auf den Stack: `esp` wird um 4 kleiner (16 Bit: `sp` um 2), dann wird der Wert an `[esp]` geschrieben.

**Syntax:** `push quelle`

- Quelle: Register, Speicher oder Zahl

**Flags:** keine

```asm
push 0           ; Parameter
call [ExitProcess]
```

Unter Windows (stdcall/cdecl) werden die Parameter einer Funktion mit `push` von rechts nach links übergeben; der erste Parameter wird also zuletzt gelegt.

Verwandt: `pop`, `call`

## pop – vom Stack holen

Holt den obersten Wert vom Stack: Er wird aus `[esp]` gelesen, dann wird `esp` um 4 größer (16 Bit: `sp` um 2).

**Syntax:** `pop ziel`

- Ziel: Register oder Speicher

**Flags:** keine

```asm
push ebx         ; ebx sichern
; ... ebx benutzen ...
pop ebx          ; zurückholen
```

Verwandt: `push`, `ret`

## call – Unterprogramm aufrufen

Legt die Adresse des nächsten Befehls (die Rücksprungadresse) auf den Stack und springt zum Ziel. Das Unterprogramm kehrt mit `ret` dorthin zurück.

**Syntax:** `call ziel`

- Ziel: Label, Register oder Speicher (indirekt)

**Flags:** keine

```asm
call ausgabe       ; direkt
call [ExitProcess] ; über die IAT
call eax           ; in eax
```

`call [ExitProcess]` ist der übliche Aufruf einer Windows-Funktion: In der Importtabelle (IAT) trägt Windows beim Laden die Adresse der Funktion ein.

Verwandt: `ret`, `jmp`, `push`

## ret, retn, retf – aus Unterprogramm zurückkehren

Holt die Rücksprungadresse vom Stack und springt dorthin, also hinter das `call`.

**Syntax:** `ret` oder `ret zahl`

- Mit Zahl: entfernt danach zusätzlich so viele Bytes vom Stack, z. B. die Parameter (stdcall).
- `retf`: Rückkehr aus einem Far-Call (16 Bit: Segment und Offset).

**Flags:** keine

```asm
quadrat:
    mov eax, [esp+4] ; Parameter
    imul eax, eax
    ret 4    ; 4 Bytes weg
```

Verwandt: `call`, `pop`

## add – addieren

Addiert die Quelle zum Ziel: `ziel = ziel + quelle`.

**Syntax:** `add ziel, quelle`

- Ziel: Register oder Speicher
- Quelle: Register, Speicher oder Zahl (nicht beide Speicher)

**Flags:** OF, SF, ZF, AF, CF, PF nach dem Ergebnis

```asm
add eax, 10      ; eax = eax + 10
add esp, 8       ; 2 Parameter weg
```

Verwandt: `sub`, `inc`, `adc`

## inc – um 1 erhöhen

Erhöht das Ziel um 1: `ziel = ziel + 1`.

**Syntax:** `inc ziel`

- Ziel: Register oder Speicher

**Flags:** OF, SF, ZF, AF, PF; **CF bleibt unverändert** (anders als bei `add ziel, 1`)

```asm
inc ecx          ; Zähler + 1
```

Verwandt: `dec`, `add`

## dec – um 1 verringern

Verringert das Ziel um 1: `ziel = ziel - 1`.

**Syntax:** `dec ziel`

- Ziel: Register oder Speicher

**Flags:** OF, SF, ZF, AF, PF; **CF bleibt unverändert**

```asm
schleife:
    ; ...
    dec ecx
    jnz schleife ; bis ecx = 0
```

Verwandt: `inc`, `sub`, `loop`, `jnz`

## xor – exklusives Oder

Verknüpft Ziel und Quelle Bit für Bit: Ein Bit des Ergebnisses ist 1, wenn genau eines der beiden Bits 1 ist.

**Syntax:** `xor ziel, quelle`

- Ziel: Register oder Speicher
- Quelle: Register, Speicher oder Zahl

**Flags:** OF = 0, CF = 0; SF, ZF, PF nach dem Ergebnis

```asm
xor eax, eax     ; eax = 0
xor al, 0x20     ; Bit 5 kippen
```

Verwandt: `and`, `or`, `not`

## cmp – vergleichen

Vergleicht zwei Werte: Rechnet `ziel - quelle`, speichert das Ergebnis aber nicht, sondern setzt nur die Flags. Danach entscheidet ein bedingter Sprung.

**Syntax:** `cmp ziel, quelle`

- Ziel: Register oder Speicher
- Quelle: Register, Speicher oder Zahl

**Flags:** OF, SF, ZF, AF, CF, PF wie bei `sub`

```asm
cmp eax, 10
jz zehn          ; wenn eax = 10
jb kleiner       ; wenn eax < 10
```

Verwandt: `test`, `sub`, bedingte Sprünge (`jz`, `jnz`, ...)

## jcc – bedingte Sprünge
<!-- names: jz, je, jnz, jne, jc, jb, jnae, jnc, jae, jnb, ja, jnbe, jbe, jna, jl, jnge, jge, jnl, jg, jnle, jle, jng, js, jns, jo, jno, jp, jpe, jnp, jpo -->

Springen zum Ziel, wenn die Bedingung erfüllt ist; sonst geht es mit dem nächsten Befehl weiter. Die Bedingung prüft die Flags, meist nach `cmp`, `test` oder einer Rechnung.

**Syntax:** `jcc ziel` (Ziel: Label)

Nach `cmp a, b`:

- `jz`/`je`: a = b (ZF = 1); `jnz`/`jne`: a ungleich b (ZF = 0)
- ohne Vorzeichen: `jb`/`jc` a < b (CF = 1), `jae`/`jnc` a >= b, `ja` a > b, `jbe` a <= b
- mit Vorzeichen: `jl` a < b, `jge` a >= b, `jg` a > b, `jle` a <= b
- `js`/`jns`: Ergebnis negativ / nicht negativ; `jo`/`jno`: Überlauf / keiner; `jp`/`jnp`: Parität

Mehrere Namen sind derselbe Befehl, z. B. `jz` und `je`; Dismonite schreibt die Form mit `z`.

**Flags:** keine geändert, nur gelesen

```asm
    mov ecx, 5
schleife:
    ; ...
    dec ecx
    jnz schleife ; bis ecx = 0
```

Verwandt: `cmp`, `test`, `jmp`, `loop`

## jmp – springen

Springt immer zum Ziel.

**Syntax:** `jmp ziel`

- Ziel: Label, Register oder Speicher (indirekt)

**Flags:** keine

```asm
jmp ende            ; direkt
jmp [tabelle+eax*4] ; Tabelle
```

Verwandt: bedingte Sprünge (`jz`, ...), `call`

## nop – nichts tun

Tut nichts außer zum nächsten Befehl weiterzugehen. Dient als Füllbyte, z. B. damit eine Funktion an einer runden Adresse beginnt.

**Syntax:** `nop`

**Flags:** keine

Code: `90`

## db, dw, dd, dq – Daten

Legt Bytes in die Datei: `db` je ein Byte, `dw` ein Wort (2 Bytes), `dd` ein Doppelwort (4 Bytes), `dq` 8 Bytes. Mehrere Werte durch Kommas getrennt; bei `db` auch Text in Anführungszeichen. Bei `dw 0x5A4D` stehen die Bytes `4D 5A` in der Datei: x86 speichert das niedrige Byte zuerst (Little Endian).

**Syntax:** `db wert, ...`

```asm
db 'Hallo',13,10,0  ; Text
dw 0x5A4D           ; 'MZ'
dd 0x00401000
```

In Dismonite sind Zeilen mit `db`/`dw`/`dd` Daten: Bytes, die nicht als Befehl gelesen werden. In den Strukturen des Dateiformats (PE-Header usw.) steht im Kommentar der Name des Felds.

Verwandt: `rva`, `org`, `align`

## resb, resw, resd, resq – Platz reservieren

Reserviert Speicher ohne Dateibytes (uninitialisierte Daten, `.bss`): `resb` je ein Byte, `resw` Wörter, `resd` Doppelwörter, `resq` Qwords; die Zahl sagt, wie viele. Der Windows-Lader füllt den Platz beim Start mit Nullen, in der Datei steht nichts davon. Im Assembler (`.format pe`) darf `resb` am Ende einer Section stehen.

**Syntax:** `resb anzahl`

```asm
buffer: resb 4096   ; 4096 Bytes
count:  resd 1      ; ein Doppelwort
```

In Dismonite sind das die Zeilen im Speicher hinter der Datei (Labels `V...`); mit B, W, D, Q legst du fest, wie groß eine Variable ist.

Verwandt: `db`, `align`

## func – eine Funktion mit Stackframe

Schreibt den Stackframe einer Funktion für dich: `push ebp / mov ebp, esp / sub esp, n` bei `begin`, den passenden Epilog bei `end` und bei jedem einzelnen `ret` darin. Parameter und lokale Variablen haben Namen, der Assembler ersetzt sie durch `[ebp+x]`. Nur für `.arch i386`.

**Syntax:**

```asm
func DoStuff(count, flags:word) cdecl uses ebx, esi
  var temp, buffer:16, small:byte
begin
  mov eax, count        ; mov eax, dword [ebp+8]
  mov temp, eax         ; mov dword [ebp-4], eax
  lea edx, buffer       ; lea edx, [ebp-20]
  mov [buffer+4], eax   ; mov [ebp-16], eax
end
```

- `func Name(p1, p2:typ)` ist zugleich das Label `Name:`. Parameter sind Dword-Plätze bei `[ebp+8]`, `[ebp+12]` ...; ein Typ (`byte`, `word`, `dword`) legt nur die Zugriffsgröße fest. Standard ist `stdcall` (`ret 4*n` räumt die Argumente ab); `cdecl` endet mit einem einfachen `ret`.
- `var name, name:typ, name:N` legt Lokale unter ebp an: ein Dword, ein Byte/Word/Dword (je 4 Bytes) oder ein Feld von N Bytes. Eine Variable steht für `größe [ebp+x]`; ein Feldname für seine Adresse (`[buf+eax*4]`, `buf+4` gehen, eine Variable in `[...]` ist ein Fehler).
- `uses ebx, esi` rettet Register hinter den Lokalen und stellt sie vor dem Epilog wieder her.
- Ein einzelnes `ret` in der Funktion ist der Epilog (vorzeitiger Rücksprung); `end` fügt einen Epilog an, außer die letzte Anweisung ist `ret`.
- **Aufrufe mit Argumenten:** `call Add2(7, 5)` legt die Argumente von rechts nach links ab und ruft auf; bei einer `cdecl`-func folgt `add esp, 4*n`. Eine deklarierte func gibt ihre Konvention und ihre Parameterzahl vor (eine falsche Zahl ist ein Fehler); jedes andere Label ist `stdcall`, für cdecl schreibst du `call cdecl name(...)`. Ein Import hat die Konvention seiner `.import`-Zeile, `stdcall`, wenn die Zeile nicht `cdecl` sagt: `.import msvcrt.dll cdecl printf, scanf` (dann fügt `call [printf](fmt, 42)` das `add esp, 8` an), `.import user32.dll MessageBoxA` (stdcall). Bei einer DLL der C-Laufzeit (`msvcrt.dll`, `ucrtbase.dll`, `api-ms-win-crt-*`) ist das Wort Pflicht: ein Aufruf mit Argumenten ohne es ist ein Fehler. `call cdecl [name](...)` oder `call stdcall [name](...)` entscheidet für einen Aufruf. Ein Argument ist ein Register, eine Zahl, ein Label (seine Adresse), ein Parameter oder Local (Dword: sein Wert; Byte/Word: auf 32 Bit aufgefüllt; Feld: seine Adresse), `&name` (die Adresse eines Locals) oder `[ebx+4]`. Für eine Adresse oder ein Byte/Word nimmt der Assembler das erste von `eax`, `ecx`, `edx`, das die Argumentliste nicht nennt (Fehler, wenn alle drei genannt sind); `esp` ist in einem Argument nicht erlaubt. Das Ergebnis bleibt in `eax`.
- **`if` / `else` / `endif`** (überall im i386-Code, auch in einer func, verschachtelt): `if [signed|unsigned] a op b` ist `cmp a, b` und der Sprung der Gegenbedingung um den Block; `else` fügt ein `jmp` über den zweiten Block an. `a` und `b` sind Operanden (in einer func gehen ihre Namen), **keine Ausdrücke**: ein Vergleich, `==`, `!=`, `<`, `<=`, `>`, `>=`. `==` und `!=` brauchen kein Wort; die anderen vier sagen **`signed`** (`jge`, `jg`, `jle`, `jl` überspringen den Block) oder **`unsigned`** (`jae`, `ja`, `jbe`, `jb`); ohne das Wort ist es ein Fehler, außer davor steht **`.compare signed`** oder **`.compare unsigned`** (das Wort für alle Ifs dahinter, bis zum nächsten `.compare`; `.compare none` nimmt es zurück); ein Wort in der `if`-Zeile gilt immer. Speicher gegen eine Zahl braucht die Größe: `if dword [x] == 5`. **`if a & b`** ist `test a, b` und `jz` um den Block (er läuft, wenn in beiden ein Bit gesetzt ist), `if a & b == 0` ist `test` und `jnz`, `if a & b != 0` ist dasselbe wie `if a & b`; dabei kein `signed` / `unsigned`, dahinter nichts anderes. Die erzeugten Labels heißen `asmogen_if<Zeile>e` und `x`. **`if zero`**, `if not carry`, `if below or equal` ... nennen die Bedingung mit einem Flag-Wort: kein `cmp`, nur der Sprung um den Block (die Flags des Befehls davor zählen); die Wörter `zero` (`equal`), `carry`, `sign`, `overflow`, `parity`, `above` / `below` (ohne Vorzeichen), `less` / `greater` (mit Vorzeichen), `not` davor, `or equal` hinter above / below / less / greater. **`do` ... `while <Bedingung>`** lässt den Block einmal und dann so lange laufen, wie die Bedingung gilt (die Formen des `if`; der Sprung zurück ist die Bedingung selbst: `while not zero` ist `jnz`); `do` und `while` dürfen keine func, keinen Parameter und kein Lokales benennen; Beispiel `examples/func/func_loop.asm`. Beispiel: `examples/func/func_if.asm`.
- Namen dürfen keine Register, Befehle oder Schlüsselwörter sein. Die Fehler zeigen die Zeile des Quelltexts.

Siehe auch: `call`, `ret`, `push`

## rva – relative Adresse

Schreibt die Adresse eines Labels als RVA (relative virtuelle Adresse): die Adresse im Speicher minus die Basisadresse des Programms (`.imagebase`). Das ist ein Doppelwort (4 Bytes).

**Syntax:** `rva label`

```asm
rva start  ; start - imagebase
```

PE-Dateien geben Adressen fast überall als RVA an, damit Windows das Programm auch an eine andere Basis laden kann.

Verwandt: `dd`, `org`

## org – Position festlegen

Setzt die Position in der Datei: Die folgenden Bytes beginnen an diesem Offset. Bis dorthin wird mit Nullen aufgefüllt.

**Syntax:** `org offset`

```asm
org 0x3C   ; Offset von e_lfanew
dd 0x00000080
```

Dismonite schreibt `org` dort, wo vor einer Struktur nur Nullen stehen; die Nullen erscheinen dann nicht als eigene Zeilen.

Verwandt: `align`, `db`

## align – auf Grenze auffüllen

Füllt mit Nullen auf, bis die Position durch die Zahl teilbar ist. In PE-Dateien beginnt so jede Section an einem Vielfachen von `FileAlignment`.

**Syntax:** `align zahl`

```asm
align 0x200 ; FileAlignment 512
```

Verwandt: `org`

## sub – subtrahieren

Zieht die Quelle vom Ziel ab: `ziel = ziel - quelle`.

**Syntax:** `sub ziel, quelle`

- Ziel: Register oder Speicher
- Quelle: Register, Speicher oder Zahl (nicht beide Speicher)

**Flags:** OF, SF, ZF, AF, CF, PF nach dem Ergebnis; CF = 1, wenn ohne Vorzeichen ein „Borgen“ nötig war (Quelle größer als Ziel)

```asm
sub eax, 4       ; eax = eax - 4
sub esp, 0x20    ; Platz für
                 ; lokale Werte
```

Verwandt: `add`, `sbb`, `dec`, `cmp`, `neg`

## adc – addieren mit Übertrag

Addiert Quelle und Carry-Flag zum Ziel: `ziel = ziel + quelle + CF`. So lassen sich Zahlen addieren, die größer als ein Register sind: erst die unteren Teile mit `add`, dann die oberen mit `adc`.

**Syntax:** `adc ziel, quelle`

**Flags:** OF, SF, ZF, AF, CF, PF nach dem Ergebnis

```asm
add eax, ebx  ; untere 32 Bit
adc edx, ecx  ; obere + CF
```

Verwandt: `add`, `sbb`, `clc`, `stc`

## sbb – subtrahieren mit Borgen

Zieht Quelle und Carry-Flag vom Ziel ab: `ziel = ziel - quelle - CF`. Das Gegenstück zu `adc` für große Zahlen.

**Syntax:** `sbb ziel, quelle`

**Flags:** OF, SF, ZF, AF, CF, PF nach dem Ergebnis

```asm
sub eax, ebx  ; untere 32 Bit
sbb edx, ecx  ; obere - CF
sbb eax, eax  ; 0 oder -1
```

Der Trick `sbb eax, eax` macht aus dem Carry-Flag eine Maske: 0, wenn CF = 0, sonst -1 (alle Bits 1).

Verwandt: `sub`, `adc`

## and – Und

Verknüpft Ziel und Quelle Bit für Bit: Ein Bit des Ergebnisses ist nur 1, wenn beide Bits 1 sind. Damit löscht man Bits (Maske).

**Syntax:** `and ziel, quelle`

**Flags:** OF = 0, CF = 0; SF, ZF, PF nach dem Ergebnis

```asm
and eax, 0xFF ; unterstes Byte
and esp, -16  ; auf 16 abrunden
```

Verwandt: `or`, `xor`, `not`, `test`

## or – Oder

Verknüpft Ziel und Quelle Bit für Bit: Ein Bit des Ergebnisses ist 1, wenn mindestens eines der beiden Bits 1 ist. Damit setzt man Bits.

**Syntax:** `or ziel, quelle`

**Flags:** OF = 0, CF = 0; SF, ZF, PF nach dem Ergebnis

```asm
or eax, 0x80  ; Bit 7 setzen
or eax, eax   ; ZF=1 bei eax=0
```

`or eax, eax` (oder `test eax, eax`) prüft ein Register auf 0, ohne es zu ändern.

Verwandt: `and`, `xor`, `test`

## not – Bits umkehren

Kehrt jedes Bit des Ziels um (Einerkomplement): aus 0 wird 1 und aus 1 wird 0.

**Syntax:** `not ziel`

- Ziel: Register oder Speicher

**Flags:** keine

```asm
not eax          ; eax = -eax - 1
```

Verwandt: `neg`, `xor`, `and`

## neg – Vorzeichen umkehren

Macht aus dem Ziel seine negative Zahl (Zweierkomplement): `ziel = 0 - ziel`.

**Syntax:** `neg ziel`

**Flags:** CF = 0, wenn das Ziel 0 war, sonst 1; OF, SF, ZF, AF, PF nach dem Ergebnis

```asm
neg eax          ; 5 wird -5
```

Verwandt: `not`, `sub`

## test – Bits prüfen

Verknüpft Ziel und Quelle wie `and`, speichert das Ergebnis aber nicht, sondern setzt nur die Flags. Danach entscheidet ein bedingter Sprung.

**Syntax:** `test ziel, quelle`

**Flags:** OF = 0, CF = 0; SF, ZF, PF nach dem Ergebnis

```asm
test eax, eax
jz null       ; wenn eax = 0
test al, 1
jnz ungerade  ; Bit 0 gesetzt
```

Verwandt: `cmp`, `and`, bedingte Sprünge (`jz`, ...)

## mul – multiplizieren ohne Vorzeichen

Multipliziert den Akkumulator mit dem Operanden. Das Ergebnis ist doppelt so breit:

- 8 Bit: `ax = al * quelle`
- 16 Bit: `dx:ax = ax * quelle`
- 32 Bit: `edx:eax = eax * quelle`

**Syntax:** `mul quelle` (Register oder Speicher, keine Zahl)

**Flags:** CF = OF = 1, wenn die obere Hälfte des Ergebnisses nicht 0 ist; SF, ZF, AF, PF undefiniert

```asm
mov eax, 1000
mul ecx       ; edx:eax=eax*ecx
```

Verwandt: `imul`, `div`

## imul – multiplizieren mit Vorzeichen

Multipliziert Zahlen mit Vorzeichen. Drei Formen:

- `imul quelle`: wie `mul`, Ergebnis in `edx:eax` (16 Bit: `dx:ax`)
- `imul ziel, quelle`: `ziel = ziel * quelle`
- `imul ziel, quelle, zahl`: `ziel = quelle * zahl`

Bei den Formen mit Ziel wird nur die untere Hälfte behalten.

**Flags:** CF = OF = 1, wenn das Ergebnis nicht in das Ziel passt

```asm
imul eax, ecx     ; eax*=ecx
imul eax, [esi],12 ; *12
```

Verwandt: `mul`, `idiv`

## div – teilen ohne Vorzeichen

Teilt den doppelt breiten Akkumulator durch den Operanden; Quotient und Rest:

- 8 Bit: `ax / quelle`, Quotient `al`, Rest `ah`
- 16 Bit: `dx:ax / quelle`, Quotient `ax`, Rest `dx`
- 32 Bit: `edx:eax / quelle`, Quotient `eax`, Rest `edx`

**Syntax:** `div quelle` (Register oder Speicher)

Teilen durch 0 oder ein Quotient, der nicht passt, löst eine Ausnahme aus (Interrupt 0). Deshalb vorher `edx` auf 0 setzen.

**Flags:** undefiniert

```asm
xor edx, edx     ; obere Hälfte 0
mov ecx, 10
div ecx          ; eax = eax/10,
                 ; edx = Rest
```

Verwandt: `idiv`, `mul`, `cdq`

## idiv – teilen mit Vorzeichen

Wie `div`, aber mit Vorzeichen. Vorher wird der Akkumulator mit `cdq` (16 Bit: `cwd`, 8 Bit: `cbw`) auf die doppelte Breite mit Vorzeichen erweitert.

**Syntax:** `idiv quelle`

Der Rest hat das Vorzeichen des Dividenden: -7 / 2 ergibt -3, Rest -1.

**Flags:** undefiniert

```asm
cdq           ; edx = Vorzeichen
idiv ecx      ; edx:eax / ecx
```

Verwandt: `div`, `imul`, `cdq`, `cwd`

## lea – Adresse berechnen

Berechnet die Adresse des Speicheroperanden und schreibt sie ins Ziel. Es wird nichts aus dem Speicher gelesen. Weil die Adressrechnung Register addieren und mit 2, 4 oder 8 malnehmen kann, dient `lea` auch als schnelle Rechnung.

**Syntax:** `lea ziel, [adresse]` (Ziel: Register)

**Flags:** keine

```asm
lea esi, [text]   ; esi = Adresse
lea eax, [ebx+ecx*4+8]
lea eax, [eax+eax*2] ; eax*3
```

Verwandt: `mov`

## xchg – vertauschen

Vertauscht die Werte von Ziel und Quelle. Mit einem Speicheroperanden geschieht das atomar (wie mit `lock`), für Sperren zwischen Threads.

**Syntax:** `xchg ziel, quelle` (mindestens ein Register)

**Flags:** keine

```asm
xchg eax, ebx
xchg eax, eax    ; = nop (90)
```

Verwandt: `mov`, `lock`

## movzx – kopieren mit Nullen erweitert

Kopiert ein Byte oder Wort in ein größeres Register und füllt die oberen Bits mit 0 auf (ohne Vorzeichen).

**Syntax:** `movzx ziel, quelle` (Ziel: Register 16/32 Bit; Quelle: 8 oder 16 Bit)

**Flags:** keine

```asm
movzx eax, byte [esi] ; 0..255
movzx ecx, ax
```

Verwandt: `movsx`, `mov`

## movsx – kopieren mit Vorzeichen erweitert

Kopiert ein Byte oder Wort in ein größeres Register und füllt die oberen Bits mit dem Vorzeichenbit auf: -1 bleibt -1.

**Syntax:** `movsx ziel, quelle`

**Flags:** keine

```asm
movsx eax, byte [esi] ; -128..127
```

Verwandt: `movzx`, `cbw`, `cwde`

## cbw, cwde – Akkumulator mit Vorzeichen erweitern

Erweitert den Akkumulator auf die doppelte Breite, mit Vorzeichen:

- `cbw`: `al` nach `ax` (16 Bit)
- `cwde`: `ax` nach `eax` (32 Bit)

Es ist derselbe Code (98); welcher Name gilt, hängt von der Operandengröße ab.

**Flags:** keine

Verwandt: `cwd`, `cdq`, `movsx`

## cwd, cdq – für Division mit Vorzeichen vorbereiten

Füllt das Register darüber mit dem Vorzeichen des Akkumulators:

- `cwd`: `dx:ax` aus `ax` (16 Bit)
- `cdq`: `edx:eax` aus `eax` (32 Bit)

Danach kann `idiv` teilen. Code 99, Name nach Operandengröße.

**Flags:** keine

```asm
mov eax, -7
cdq              ; edx = -1
idiv ecx
```

Verwandt: `idiv`, `cbw`, `cwde`

## shl, sal – nach links schieben

Schiebt die Bits des Ziels nach links; rechts kommen Nullen nach. Jede Stelle verdoppelt den Wert. `shl` und `sal` sind derselbe Befehl.

**Syntax:** `shl ziel, anzahl` (Anzahl: 1, Zahl oder `cl`)

**Flags:** CF = das zuletzt hinausgeschobene Bit; SF, ZF, PF nach dem Ergebnis; OF nur bei 1 Stelle definiert

```asm
shl eax, 2       ; eax * 4
shl edx, cl
```

Verwandt: `shr`, `sar`, `rol`, `shld`

## shr – nach rechts schieben (ohne Vorzeichen)

Schiebt die Bits nach rechts; links kommen Nullen nach. Jede Stelle halbiert den Wert ohne Vorzeichen (abgerundet).

**Syntax:** `shr ziel, anzahl`

**Flags:** CF = das zuletzt hinausgeschobene Bit; SF, ZF, PF nach dem Ergebnis

```asm
shr eax, 4       ; eax / 16
```

Verwandt: `sar`, `shl`, `shrd`

## sar – nach rechts schieben (mit Vorzeichen)

Schiebt nach rechts; links wird das Vorzeichenbit wiederholt. So wird eine Zahl mit Vorzeichen halbiert (zu minus unendlich gerundet: -7 sar 1 ist -4).

**Syntax:** `sar ziel, anzahl`

**Flags:** CF = das zuletzt hinausgeschobene Bit; SF, ZF, PF nach dem Ergebnis

```asm
sar eax, 31      ; 0 oder -1
```

Verwandt: `shr`, `idiv`

## rol, ror – rotieren

Schiebt die Bits im Kreis: Was auf einer Seite hinausgeht, kommt auf der anderen wieder herein. `rol` nach links, `ror` nach rechts.

**Syntax:** `rol ziel, anzahl`

**Flags:** CF = das Bit, das herumgewandert ist; OF nur bei 1 Stelle; die übrigen bleiben

```asm
rol eax, 8       ; Bytes drehen
ror ax, 8        ; = xchg al, ah
```

Verwandt: `rcl`, `rcr`, `shl`

## rcl, rcr – rotieren durch das Carry-Flag

Wie `rol`/`ror`, aber das Carry-Flag gehört mit zum Kreis: Das hinausgehende Bit kommt nach CF, der alte Wert von CF kommt herein. Damit schiebt man Zahlen über mehrere Register.

**Syntax:** `rcl ziel, anzahl`

**Flags:** CF; OF nur bei 1 Stelle

```asm
shl eax, 1       ; Bit 31 -> CF
rcl edx, 1       ; CF -> Bit 0
```

Verwandt: `rol`, `ror`, `shld`

## shld, shrd – doppelt schieben

Schiebt das Ziel und füllt die frei werdenden Bits aus einem zweiten Register (das selbst unverändert bleibt). So schiebt man 64-Bit-Werte in zwei Registern.

**Syntax:** `shld ziel, quelle, anzahl` (Anzahl: Zahl oder `cl`)

**Flags:** CF = das zuletzt hinausgeschobene Bit; SF, ZF, PF nach dem Ergebnis

```asm
shld edx, eax, 4 ; edx:eax << 4
shl eax, 4
```

Verwandt: `shl`, `shr`

## bt, bts, btr, btc – einzelnes Bit prüfen

Kopiert ein Bit des Ziels in das Carry-Flag:

- `bt`: nur prüfen
- `bts`: danach setzen (1)
- `btr`: danach löschen (0)
- `btc`: danach umkehren

**Syntax:** `bt ziel, nummer` (Nummer: Register oder Zahl)

**Flags:** CF = das alte Bit

```asm
bt eax, 5
jc gesetzt       ; wenn Bit 5 = 1
```

Verwandt: `test`, `and`, `or`

## bsf, bsr – Bit suchen

Sucht das erste gesetzte Bit der Quelle und schreibt seine Nummer ins Ziel: `bsf` vom niedrigsten Bit an, `bsr` vom höchsten.

**Syntax:** `bsf ziel, quelle`

**Flags:** ZF = 1, wenn die Quelle 0 ist (dann ist das Ziel undefiniert)

```asm
bsr ecx, eax     ; höchstes Bit
jz null
```

Verwandt: `bt`, `test`

## setcc – Byte nach Bedingung setzen
<!-- names: setz, sete, setnz, setne, setc, setb, setnae, setnc, setae, setnb, seta, setnbe, setbe, setna, setl, setnge, setge, setnl, setg, setnle, setle, setng, sets, setns, seto, setno, setp, setpe, setnp, setpo -->

Schreibt 1 in ein Byte, wenn die Bedingung erfüllt ist, sonst 0. Die Bedingungen sind dieselben wie bei den bedingten Sprüngen (`setz` wie `jz` usw.).

**Syntax:** `setcc ziel` (Ziel: 8-Bit-Register oder Byte im Speicher)

**Flags:** keine geändert, nur gelesen

```asm
cmp eax, ebx
setz al        ; 1, wenn gleich
movzx eax, al  ; als 32 Bit
```

Verwandt: bedingte Sprünge (`jz`, ...), `cmp`, `test`

## cmovcc – kopieren nach Bedingung
<!-- names: cmovz, cmove, cmovnz, cmovne, cmovc, cmovb, cmovnae, cmovnc, cmovae, cmovnb, cmova, cmovnbe, cmovbe, cmovna, cmovl, cmovnge, cmovge, cmovnl, cmovg, cmovnle, cmovle, cmovng, cmovs, cmovns, cmovo, cmovno, cmovp, cmovpe, cmovnp, cmovpo -->

Kopiert die Quelle nur dann in das Ziel, wenn die Bedingung erfüllt ist, sonst geschieht nichts. Das ersetzt einen kurzen bedingten Sprung: Es gibt keinen Sprung, den der Prozessor raten müsste. Die Bedingungen sind dieselben wie bei den bedingten Sprüngen (`cmovz` wie `jz` usw.). Seit dem Pentium Pro. Eine Quelle im Speicher wird auch gelesen, wenn die Bedingung nicht erfüllt ist.

**Syntax:** `cmovcc ziel, quelle` (Ziel: Register, Quelle: Register oder Speicher)

**Flags:** keine geändert, nur gelesen

```asm
cmp eax, ebx
cmovl eax, ebx    ; eax = der größere von beiden (mit Vorzeichen)
```

Verwandt: bedingte Sprünge (`jz`, ...), `setcc`, `cmp`, `mov`

## bswap – Bytereihenfolge umkehren

Kehrt die Reihenfolge der vier Bytes eines 32-Bit-Registers um: Aus `0x11223344` wird `0x44332211`. Damit wandelt man zwischen Little Endian (x86) und Big Endian (Netzwerk-Bytereihenfolge, viele Dateiformate) um. Seit dem 486. Nur 32-Bit-Register; für einen 16-Bit-Wert nimmt man `xchg al, ah` oder `ror ax, 8`.

**Syntax:** `bswap reg32`

**Flags:** keine

```asm
mov eax, 0x11223344
bswap eax         ; eax = 0x44332211
```

Verwandt: `xchg`, `ror`, `rol`

## xadd – vertauschen und addieren

Addiert die Quelle zum Ziel und legt den alten Wert des Ziels in die Quelle. Mit `lock` ist das ein atomares „holen und addieren“: Zähler, die mehrere Threads benutzen. Seit dem 486.

**Syntax:** `xadd ziel, quelle` (Ziel: Register oder Speicher, Quelle: Register)

**Flags:** wie `add`

```asm
mov eax, 1
lock xadd [zaehler], eax   ; zaehler + 1, eax = der alte Wert
```

Verwandt: `add`, `xchg`, `lock`, `cmpxchg`

## cmpxchg, cmpxchg8b – vergleichen und vertauschen

`cmpxchg` vergleicht den Akkumulator (`al`, `ax`, `eax`) mit dem Ziel. Gleich: Die Quelle wird in das Ziel geschrieben und ZF = 1. Ungleich: Das Ziel wird in den Akkumulator geladen und ZF = 0. Mit `lock` ist es atomar: die Grundlage von Spinlocks und sperrfreien Datenstrukturen. `cmpxchg8b` macht dasselbe mit 64 Bit, mit `edx:eax` (erwartet) und `ecx:ebx` (neu). Seit dem 486 (`cmpxchg8b`: Pentium).

**Syntax:** `cmpxchg ziel, quelle` (Ziel: Register oder Speicher, Quelle: Register); `cmpxchg8b mem64`

**Flags:** ZF wie beschrieben; `cmpxchg` setzt die übrigen wie `cmp`, `cmpxchg8b` nur ZF

```asm
xor eax, eax                ; erwartet: 0, die Sperre ist frei
mov ecx, 1                  ; neu: belegt
lock cmpxchg [sperre], ecx
jnz belegt                  ; ZF = 0: jemand anders hat sie
```

Verwandt: `xchg`, `xadd`, `lock`, `pause`

## cpuid – den Prozessor fragen

Liefert Angaben über den Prozessor in `eax`, `ebx`, `ecx` und `edx`; die Funktionsnummer steht in `eax` (bei einigen Funktionen auch in `ecx`). Funktion 0 gibt die höchste Funktionsnummer und den Herstellernamen in `ebx`, `edx`, `ecx` (`GenuineIntel`, `AuthenticAMD`), Funktion 1 das Modell und die Merkmalsbits (SSE, ...), ab `0x80000000` kommen die erweiterten Funktionen. Überschreibt `eax`, `ebx`, `ecx` und `edx`.

**Syntax:** `cpuid`

**Flags:** keine

```asm
xor eax, eax
cpuid             ; eax = höchste Funktion, ebx, edx, ecx = Herstellername
```

Verwandt: `rdtsc`

## rdtsc – den Zeitzähler lesen

Liest den 64-Bit-Zähler der Prozessortakte nach `edx:eax` (der obere Teil in `edx`). Gut, um kurze Zeiten zu messen; der Zähler läuft weiter, während das Programm wartet oder ein anderes läuft, und die Kerne eines Prozessors können voneinander abweichen. Seit dem Pentium.

**Syntax:** `rdtsc`

**Flags:** keine

```asm
rdtsc
mov esi, eax      ; unterer Teil: der Anfang
; ... der Code, der gemessen wird ...
rdtsc
sub eax, esi      ; Takte
```

Verwandt: `cpuid`

## pause – Hinweis in einer Warteschleife

Ein Hinweis an den Prozessor in einer Schleife, die darauf wartet, dass sich ein Wert ändert: Er spart Strom und vermeidet eine Verzögerung am Ende der Schleife. Er ist als `rep nop` (`F3 90`) kodiert, ältere Prozessoren führen also nur ein `nop` aus. Seit dem Pentium 4.

**Syntax:** `pause`

**Flags:** keine

```asm
warten:
  pause
  cmp dword [flagge], 0
  jz warten
```

Verwandt: `nop`, `lock`, `cmpxchg`

## ud2 – undefinierter Befehl

Löst immer die Ausnahme „ungültiger Befehl“ aus (`0F 0B`): Das Programm wird beendet, ein Debugger hält dort an. Wird für Stellen benutzt, die nie erreicht werden dürfen, z. B. hinter einem Aufruf, der nicht zurückkehrt.

**Syntax:** `ud2`

**Flags:** keine

Verwandt: `int3`, `hlt`, `int`

## int3 – Breakpoint

Ein Ein-Byte-Interrupt (`CC`), der die Ausnahme „Breakpoint“ auslöst. Debugger legen ihn über das erste Byte eines Befehls, um dort anzuhalten. Ohne Debugger endet das Programm. Compiler und Windows benutzen `CC` auch als Füllbytes zwischen Funktionen, eine lange Reihe `int3` in einem Disassembler-Listing ist also nur Füllung. Der Assembler von Asmonite kennt den Namen `int3` nicht, schreibe `int 3`.

**Syntax:** `int3`

**Flags:** keine

Verwandt: `int`, `ud2`, `hlt`

## sysenter, sysexit – schneller Systemaufruf

`sysenter` springt ohne das langsame Interrupt-Gate in den Kernel; Windows und Linux benutzen es in ihren Systemaufruf-Stubs (die Funktionsnummer steht in `eax`). `sysexit` kehrt zum Programm zurück und ist nur im Kernelmodus erlaubt. `sysenter` sieht man in `ntdll.dll`, nicht in normalen Programmen. 64-Bit-Programme benutzen dafür `syscall`.

**Syntax:** `sysenter`, `sysexit`

**Flags:** vom Systemaufruf geändert

Verwandt: `int`, `iret`

## popcnt, lzcnt, tzcnt – Bits zählen

`popcnt` zählt die gesetzten Bits der Quelle, `lzcnt` die Nullbits oberhalb des höchsten gesetzten Bits (führende Nullen), `tzcnt` die Nullbits unterhalb des niedrigsten gesetzten Bits (nachfolgende Nullen). `lzcnt` und `tzcnt` sind als `rep bsr` und `rep bsf` kodiert: Ein Prozessor ohne sie führt `bsr` und `bsf` aus, die ein anderes Ergebnis geben (die Bitnummer, nicht die Anzahl).

**Syntax:** `popcnt ziel, quelle` (Ziel: Register, Quelle: Register oder Speicher); ebenso `lzcnt` und `tzcnt`

**Flags:** `popcnt`: ZF = 1, wenn die Quelle 0 ist, die übrigen werden gelöscht. `lzcnt`, `tzcnt`: CF = 1, wenn die Quelle 0 ist, ZF = 1, wenn das Ergebnis 0 ist

```asm
popcnt ecx, eax    ; Anzahl der gesetzten Bits in eax
tzcnt edx, eax     ; Nummer des niedrigsten gesetzten Bits (32, wenn eax = 0)
```

Verwandt: `bsf`, `bsr`, `bt`

## movsxd – kopieren mit Vorzeichen erweitert (32 auf 64 Bit)

Kopiert einen 32-Bit-Wert (Register oder Speicher) in ein 64-Bit-Register und füllt die obere Hälfte mit dem Vorzeichenbit. Nur im 64-Bit-Modus. Ein einfaches `mov eax, ...` macht das Gegenteil: Es schreibt die untere Hälfte und löscht die obere. Ein 32-Bit-Wert mit Vorzeichen (ein C-`int`), der als 64-Bit-Zahl oder Index dient, braucht deshalb `movsxd`.

**Syntax:** `movsxd ziel64, quelle32` (Quelle: 32-Bit-Register oder Speicher)

**Flags:** keine

```asm
movsxd rax, ecx           ; rax = (64 Bit) ecx, mit Vorzeichen
movsxd rdx, dword [rbx+4]
```

Verwandt: `movsx`, `movzx`, `cdqe`, `mov`

## cdqe, cqo – rax erweitern, 64-Bit-Division vorbereiten

`cdqe` erweitert `eax` mit Vorzeichen auf `rax` (wie `cwde` `ax` auf `eax`). `cqo` füllt `rdx` mit dem Vorzeichen von `rax`: `rdx:rax` ist dann die 128-Bit-Zahl für eine 64-Bit-Division mit Vorzeichen durch `idiv`. Die 32-Bit-Formen sind `cwde` und `cdq`.

**Syntax:** `cdqe`, `cqo`

**Flags:** keine

```asm
mov rax, [zahl]
cqo               ; rdx:rax = rax mit Vorzeichen
idiv rcx          ; rax = Quotient, rdx = Rest
```

Verwandt: `cbw`, `cwde`, `cwd`, `cdq`, `idiv`, `movsxd`

## syscall, sysret – Systemaufruf (64 Bit)

`syscall` springt in den Kernel; es ist das 64-Bit-Gegenstück zu `sysenter`. Unter Windows steht die Nummer des Dienstes in `eax`, das erste Argument in `r10` (aus `rcx` kopiert), die weiteren in `rdx`, `r8`, `r9` und auf dem Stack; jede Funktion in `ntdll.dll`, die zum Kernel führt, endet im Stub `mov r10, rcx` / `mov eax, N` / `syscall` / `ret`. Unter Linux steht die Nummer in `rax` und die Argumente in `rdi`, `rsi`, `rdx`, `r10`, `r8`, `r9`. Der Prozessor legt die Rücksprungadresse in `rcx` und die Flags in `r11` ab, beide werden also überschrieben. `sysret` kehrt zurück und ist nur im Kernelmodus erlaubt. Programme rufen die API auf, nicht `syscall`.

**Syntax:** `syscall`, `sysret`

**Flags:** die Flags gehen nach `r11`; `sysret` stellt sie wieder her

```asm
mov r10, rcx      ; das erste Argument
mov eax, 0x26     ; Nummer des Dienstes (je nach Windows-Version verschieden)
syscall
ret
```

Verwandt: `sysenter`, `int`, `call`

## rip – Adressieren relativ zum Befehlszeiger

Im 64-Bit-Modus kann Speicher als Abstand vom nächsten Befehl adressiert werden: `[rip+0x1234]` (der Assembler von Asmonite schreibt `[rel label]`, der Disassembler `[rip+...]`). Der Abstand hat 32 Bit, Daten innerhalb von 2 GB um den Code sind also ohne absolute Adresse erreichbar. Darum kann ein Programm bei jedem Start an einer anderen Adresse liegen (ASLR), ohne dass der Code geändert wird: `lea rax, [rip+x]` bildet die Adresse von Daten, `call [rip+x]` ruft über die Import-Adresstabelle auf. Das `rip` in der Adresse ist die Adresse des **nächsten** Befehls.

**Syntax:** `[rip+disp32]`, im Assembler `[rel label]`

```asm
lea rcx, [rel msg]    ; Adresse des Textes, wo auch immer das Programm liegt
call [rel printf]     ; über die Import-Adresstabelle
```

Verwandt: `lea`, `mov`, `call`, `x64`

## x64 – der 64-Bit-Modus in Kürze

**Register:** 16 allgemeine Register `rax rbx rcx rdx rsi rdi rbp rsp r8 .. r15`. Teile: `eax`/`r8d` (32 Bit), `ax`/`r8w` (16), `al`/`r8b` (8, neu: `sil dil bpl spl`). **Ein Schreiben in einen 32-Bit-Teil löscht die obere Hälfte**; bei 16 oder 8 Bit bleibt sie. `ah`..`bh` lassen sich nicht zusammen mit den neuen Registern benutzen.

**REX-Präfix** (`0x40`..`0x4F`): Seine Bits machen den Operanden 64 Bit breit (`W`) und adressieren die Register 8..15 (`R`, `X`, `B`). `48 89 D8` ist `mov rax, rbx`: derselbe Code wie in 32 Bit mit einem Byte davor. Die meisten Konstanten sind weiter 32 Bit (mit Vorzeichen erweitert); nur `mov r64, imm64` trägt 64 Bit.

**Weggefallen:** `pusha`/`popa`, `les`/`lds`, `bound`, die BCD-Befehle (`aaa`, `daa`, ...), `into`; die Ein-Byte-Formen von `inc`/`dec` (die Bytes wurden zu REX). `push` und `pop` arbeiten mit 64 Bit; `call`, `jmp`, `ret` sind 64 Bit.

**Aufrufkonvention (Windows):** die ersten vier Argumente in `rcx`, `rdx`, `r8`, `r9` (Gleitkomma in `xmm0`..`xmm3`), der Rest auf dem Stack; **der Aufrufer reserviert 32 Byte „Shadow Space“** über der Rücksprungadresse; Ergebnis in `rax` (`xmm0`); der Stack ist beim Aufruf auf 16 ausgerichtet. Die Funktion erhält: `rbx rbp rdi rsi rsp r12`..`r15`. Frei benutzbar: `rax rcx rdx r8`..`r11`.
**Linux (System V):** `rdi rsi rdx rcx r8 r9`, kein Shadow Space, erhalten: `rbx rbp r12`..`r15`.

**Adressen:** `[rip+disp]` für Daten nahe am Code, siehe `rip`.

Verwandt: `rip`, `movsxd`, `cdqe`, `syscall`, `mov`

## pusha, pushad – alle Register auf den Stack

Legt die allgemeinen Register auf den Stack, in dieser Reihenfolge: `eax`, `ecx`, `edx`, `ebx`, `esp` (der Wert vor dem Befehl), `ebp`, `esi`, `edi`. `pusha` ist die 16-Bit-Form (`ax` ... `di`).

**Flags:** keine

Verwandt: `popa`, `push`

## popa, popad – alle Register vom Stack

Holt die Register zurück, die `pusha`/`pushad` gelegt hat (in umgekehrter Reihenfolge). Der gespeicherte Wert von `esp` wird übersprungen.

**Flags:** keine

```asm
pushad           ; alles sichern
; ...
popad            ; alles zurück
```

Verwandt: `pusha`, `pop`

## pushf, pushfd – Flags auf den Stack

Legt das Flag-Register auf den Stack: `pushf` 16 Bit, `pushfd` 32 Bit (EFLAGS).

**Flags:** keine

```asm
pushf            ; Flags sichern
cli              ; Interrupts aus
; ...
popf             ; wie vorher
```

Verwandt: `popf`, `lahf`

## popf, popfd – Flags vom Stack

Holt das Flag-Register vom Stack. Manche Flags (z. B. IF, IOPL) darf nur das Betriebssystem ändern; im Benutzermodus bleiben sie.

**Flags:** alle aus dem Stack

Verwandt: `pushf`, `sahf`

## lahf, sahf – Flags und ah

`lahf` kopiert SF, ZF, AF, PF und CF nach `ah` (Bits 7, 6, 4, 2, 0); `sahf` schreibt sie von `ah` zurück in die Flags.

**Flags:** `lahf` keine; `sahf` SF, ZF, AF, PF, CF

Verwandt: `pushf`, `popf`

## clc, stc, cmc – Carry-Flag

- `clc`: CF = 0
- `stc`: CF = 1
- `cmc`: CF umkehren

Funktionen melden so oft Erfolg oder Fehler (DOS: CF = 1 nach `int 21h` heißt Fehler).

**Flags:** CF

```asm
int 0x21
jc fehler        ; CF = 1: Fehler
```

Verwandt: `adc`, `sbb`, `jc`

## cld, std – Richtung der Stringbefehle

Das Direction-Flag bestimmt, ob die Stringbefehle (`movsb`, `stosb`, `lodsb`, ...) `esi`/`edi` erhöhen oder verringern:

- `cld`: DF = 0, aufwärts (der Normalfall)
- `std`: DF = 1, abwärts

**Flags:** DF

```asm
cld
rep movsb      ; vorwärts
```

Verwandt: `movsb`, `stosb`, `rep`

## cli, sti – Interrupts sperren und erlauben

- `cli`: IF = 0, Hardware-Interrupts werden nicht angenommen
- `sti`: IF = 1, sie werden wieder angenommen

Unter DOS z. B. beim Umsetzen eines Interrupt-Vektors; unter Windows im Benutzermodus nicht erlaubt (Ausnahme).

**Flags:** IF

Verwandt: `pushf`, `popf`, `int`, `iret`

## loop – Schleife mit Zähler

Verringert `ecx` (16 Bit: `cx`) um 1 und springt zum Ziel, solange das Ergebnis nicht 0 ist.

**Syntax:** `loop ziel` (nah, -128 bis +127 Bytes)

**Flags:** keine (anders als `dec`)

```asm
    mov ecx, 10
wieder:
    ; ...
    loop wieder  ; 10 mal
```

Verwandt: `loope`, `loopne`, `jcxz`, `dec`, `jnz`

## loope, loopz, loopne, loopnz – Schleife mit Zähler und Bedingung

Wie `loop`, aber mit einer zweiten Bedingung:

- `loope`/`loopz`: weiter, solange `ecx` nicht 0 und ZF = 1
- `loopne`/`loopnz`: weiter, solange `ecx` nicht 0 und ZF = 0

**Flags:** keine geändert

```asm
suche:
    lodsb
    cmp al, ' '
    loope suche  ; Leerzeichen
```

Verwandt: `loop`, `repe`, `repne`

## jcxz, jecxz – springen, wenn Zähler 0

Springt, wenn `cx` (`jcxz`) bzw. `ecx` (`jecxz`) 0 ist. Typisch vor einer Schleife mit `loop`, damit sie bei 0 gar nicht erst läuft.

**Syntax:** `jecxz ziel` (nah, -128 bis +127 Bytes)

**Flags:** keine

```asm
jecxz fertig
wieder:
    ; ...
    loop wieder
fertig:
```

Verwandt: `loop`, `jz`

## enter – Stackrahmen anlegen

Legt den Rahmen einer Funktion an: `push ebp`, `mov ebp, esp`, `sub esp, größe`. Die zweite Zahl (Verschachtelungstiefe, meist 0) kopiert Rahmenzeiger äußerer Funktionen (Pascal).

**Syntax:** `enter größe, tiefe`

**Flags:** keine

```asm
enter 16, 0      ; 16 Bytes lokal
; ...
leave
ret
```

Verwandt: `leave`, `push`, `mov`

## leave – Stackrahmen abbauen

Baut den Rahmen ab, den `enter` (oder `push ebp` / `mov ebp, esp`) angelegt hat: `mov esp, ebp`, `pop ebp`. Danach folgt meist `ret`.

**Flags:** keine

```asm
push ebp
mov ebp, esp
sub esp, 8
; ...
leave
ret
```

Verwandt: `enter`, `ret`

## movsb, movsw, movsd – Speicher kopieren (String)

Kopiert ein Byte (`movsb`), Wort (`movsw`) oder Doppelwort (`movsd`) von `[esi]` nach `[edi]` und bewegt beide Zeiger weiter: um 1, 2 oder 4, aufwärts bei DF = 0 (`cld`), abwärts bei DF = 1. Im 16-Bit-Code `ds:si` und `es:di`.

Mit `rep` davor wird das `ecx`-mal wiederholt: ein ganzer Block.

**Flags:** keine

```asm
cld
mov esi, quelle
mov edi, ziel
mov ecx, 100
rep movsb        ; 100 Bytes
```

Verwandt: `rep`, `stosb`, `lodsb`, `cld`

## stosb, stosw, stosd – Speicher füllen (String)

Schreibt `al` (`stosb`), `ax` (`stosw`) oder `eax` (`stosd`) nach `[edi]` und bewegt `edi` weiter (Richtung nach DF). Mit `rep` wird ein Block gefüllt. Im 16-Bit-Code `es:di`.

**Flags:** keine

```asm
cld
xor eax, eax
mov ecx, 256
rep stosd        ; 1 KB nullen
```

Verwandt: `rep`, `movsb`, `lodsb`

## lodsb, lodsw, lodsd – aus Speicher laden (String)

Liest `[esi]` nach `al` (`lodsb`), `ax` (`lodsw`) oder `eax` (`lodsd`) und bewegt `esi` weiter. Typisch in Schleifen, die Text Zeichen für Zeichen lesen. Im 16-Bit-Code `ds:si`.

**Flags:** keine

```asm
weiter:
    lodsb      ; al = [esi]
    test al, al
    jnz weiter   ; bis zur 0
```

Verwandt: `stosb`, `movsb`, `loop`

## cmpsb, cmpsw, cmpsd – Speicher vergleichen (String)

Vergleicht `[esi]` mit `[edi]` (wie `cmp`, nur die Flags) und bewegt beide Zeiger weiter. Mit `repe` wird verglichen, solange die Werte gleich sind; danach zeigt ZF, ob alles gleich war.

**Flags:** wie `cmp`

```asm
mov ecx, 8
repe cmpsb       ; 8 Bytes gleich?
jnz verschieden
```

Verwandt: `scasb`, `repe`, `cmp`

## scasb, scasw, scasd – Speicher durchsuchen (String)

Vergleicht `al`/`ax`/`eax` mit `[edi]` (wie `cmp`) und bewegt `edi` weiter. Mit `repne` wird gesucht, bis der Wert gefunden ist oder `ecx` 0 wird.

**Flags:** wie `cmp`

```asm
xor al, al       ; suche die 0
mov ecx, -1
repne scasb      ; Textende finden
not ecx
dec ecx          ; ecx = Länge
```

Verwandt: `cmpsb`, `repne`

## insb, insw, insd, outsb, outsw, outsd – Port und Speicher (String)

`insb`/`insw`/`insd` lesen vom I/O-Port `dx` nach `[edi]`, `outsb`/`outsw`/`outsd` schreiben `[esi]` an den Port `dx`; der Zeiger wird weiterbewegt. Mit `rep` für ganze Blöcke. Nur für Treiber und DOS: Windows-Programme dürfen nicht auf Ports zugreifen.

**Flags:** keine

Verwandt: `in`, `out`, `rep`

## rep, repe, repz – Präfix: wiederholen

Wiederholt den folgenden Stringbefehl, bis `ecx` (16 Bit: `cx`) 0 ist; nach jeder Runde wird `ecx` um 1 verringert.

- vor `movs`, `stos`, `lods`, `ins`, `outs`: genau `ecx` mal
- vor `cmps`, `scas` (dann `repe`/`repz` genannt): außerdem nur, solange ZF = 1 (gleich)

`rep`, `repe` und `repz` sind dasselbe Byte F3.

```asm
rep stosb      ; ecx Bytes füllen
```

Verwandt: `repne`, `movsb`, `stosb`, `cmpsb`

## repne, repnz – Präfix: wiederholen, solange ungleich

Wiederholt `cmps` oder `scas`, solange `ecx` nicht 0 ist und die Werte ungleich sind (ZF = 0). Byte F2.

```asm
repne scasb      ; al suchen
```

Verwandt: `rep`, `scasb`

## lock – Präfix: atomar

Macht den folgenden Befehl mit Speicherziel (z. B. `add`, `inc`, `xchg`, `cmpxchg`) atomar: Kein anderer Prozessor kann dazwischen auf diese Speicherstelle zugreifen. Für Zähler und Sperren zwischen Threads.

```asm
lock inc dword [zaehler]
```

Verwandt: `xchg`

## cs, ds, es, ss, fs, gs – Präfix: Segment

Der Speicheroperand des folgenden Befehls gilt in diesem Segment statt im üblichen (meist `ds`, bei `esp`/`ebp` `ss`). Dismonite schreibt das Präfix als eigenes Wort vor den Befehl, z. B. `cs lodsb`.

- 16-Bit-Code (DOS): z. B. Daten im Codesegment lesen (`cs`).
- Windows: `fs:[0]` ist der Anfang des Thread-Informationsblocks (TEB); `fs:[0x30]` zeigt auf den Prozess (PEB).

```asm
mov eax, [fs:0x18] ; der TEB
```

Verwandt: `mov`, `lodsb`, `les`

## xlatb – in Tabelle nachschlagen

Ersetzt `al` durch das Byte an `[ebx + al]` (16 Bit: `[bx + al]`): ein Nachschlagen in einer Tabelle mit 256 Bytes.

**Flags:** keine

```asm
mov ebx, hex   ; '0123...ABCDEF'
and al, 0x0F
xlatb            ; al = Ziffer
```

Verwandt: `mov`, `lea`

## int, into – Interrupt auslösen

Ruft die Interrupt-Routine mit der Nummer auf: Flags, `cs` und `ip` kommen auf den Stack, dann geht es an der Adresse aus der Interrupt-Tabelle weiter; zurück mit `iret`.

- DOS: `int 0x21` ruft eine DOS-Funktion (Nummer in `ah`), `int 0x10` das Video-BIOS.
- Linux (32 Bit): `int 0x80` ruft das System (Nummer in `eax`).
- `int3` (Code CC) ist der Breakpoint eines Debuggers.
- `into`: Interrupt 4, wenn OF = 1 (Überlauf).

Windows-Programme rufen Funktionen aus DLLs, kein `int`.

**Flags:** IF und TF werden in der Routine gelöscht

```asm
mov ah, 0x09     ; Text ausgeben
mov dx, text     ; bis '$'
int 0x21
```

Verwandt: `iret`, `call`, `cli`

## iret, iretd – aus Interrupt zurückkehren

Holt `ip`, `cs` und die Flags vom Stack, die `int` (oder ein Hardware-Interrupt) gelegt hat. `iret` 16 Bit, `iretd` 32 Bit.

**Flags:** alle aus dem Stack

Verwandt: `int`, `ret`, `retf`

## hlt – anhalten

Hält den Prozessor an, bis ein Interrupt kommt. Nur für das Betriebssystem; in Windows-Programmen eine Ausnahme.

**Flags:** keine

Verwandt: `cli`, `sti`, `int`

## in – vom Port lesen

Liest einen Wert von einem I/O-Port nach `al`, `ax` oder `eax`. Die Portnummer ist eine Zahl (0 bis 255) oder steht in `dx`.

**Syntax:** `in al, port` oder `in al, dx`

Nur unter DOS und in Treibern; Windows-Programme dürfen das nicht.

**Flags:** keine

```asm
in al, 0x60      ; Tastatur-Code
```

Verwandt: `out`, `insb`

## out – auf Port schreiben

Schreibt `al`, `ax` oder `eax` an einen I/O-Port (Zahl oder `dx`).

**Syntax:** `out port, al` oder `out dx, al`

**Flags:** keine

```asm
mov al, 0x20
out 0x20, al     ; EOI an den PIC
```

Verwandt: `in`, `outsb`

## les, lds, lfs, lgs, lss – Far-Zeiger laden

Lädt einen Zeiger aus Segment und Offset (16 Bit: 4 Bytes; 32 Bit: 6 Bytes) aus dem Speicher: den Offset ins Register, das Segment in `es` (`les`), `ds` (`lds`), `fs`, `gs` oder `ss`.

**Syntax:** `les ziel, [adresse]`

Typisch im 16-Bit-Code (DOS, Turbo Pascal), um Daten in einem anderen Segment zu erreichen.

**Flags:** keine

```asm
les di, [zeiger] ; es:di = zeiger
mov al, [es:di]
```

Verwandt: `mov`, Segment-Präfixe (`es`, ...)

## bound – Index prüfen

Prüft, ob ein Register zwischen zwei Grenzen im Speicher liegt (untere Grenze, dahinter obere). Liegt es außerhalb, löst der Prozessor Interrupt 5 aus. Selten benutzt.

**Syntax:** `bound register, [grenzen]`

**Flags:** keine

Verwandt: `cmp`, `int`

## aaa, aas, aam, aad, daa, das – BCD-Rechnen

Korrigieren das Ergebnis einer Rechnung mit Dezimalziffern (BCD, eine Ziffer pro 4 oder 8 Bit):

- `aaa`, `aas`: nach `add`/`sub` mit ungepackten Ziffern (eine pro Byte)
- `daa`, `das`: nach `add`/`sub` mit gepackten Ziffern (zwei pro Byte)
- `aam`: nach `mul`: `ah = al / 10`, `al = al mod 10`
- `aad`: vor `div`: `al = ah * 10 + al`, `ah = 0`

Heute kaum noch benutzt (im 64-Bit-Modus gibt es sie nicht mehr).

**Flags:** AF und CF für den Übertrag

```asm
mov al, 0x38     ; '8'
add al, 0x35     ; + '5'
aaa              ; ah:al = 1:3
```

Verwandt: `add`, `sub`, `mul`, `div`

## wait – auf Koprozessor warten

Wartet, bis der Gleitkomma-Koprozessor (x87) fertig ist, und meldet seine anstehenden Fehler. Steht oft vor x87-Befehlen.

**Flags:** keine

Verwandt: `fpu`

## x87, fpu – die Gleitkommaeinheit (x87)

Die x87 ist die alte Gleitkommaeinheit des x86 (seit dem 8087), mit 8 Registern zu 80 Bit, die einen **Stapel** bilden:
`st0` ist oben, `st1` das darunter, bis `st7`. `fld` lädt auf den Stapel (die Werte darunter rücken eins nach unten),
`fstp` speichert das oberste und nimmt es herunter („p“ für pop); die meisten Rechenbefehle arbeiten mit `st0` und
einem anderen Register oder einem Wert im Speicher. Die Größe eines Speicheroperanden: `dword` (ein float), `qword`
(ein double), `tword` (80 Bit); `fild`/`fistp` laden und speichern ganze Zahlen.

```asm
  fild  dword [n]      ; st0 = 7 (eine ganze Zahl wird zur Gleitkommazahl)
  fld1                 ; st0 = 1, st1 = 7
  faddp st1, st0       ; st1 = st1 + st0, dann vom Stapel: st0 = 8
  fsqrt                ; st0 = 2,828...
  fistp dword [r]      ; r = 3 (gerundet), der Stapel ist wieder leer
```

- Vergleichen: `fcomip st0, st1` setzt die Flags ZF, PF, CF (danach `ja`, `jb`, `je` wie nach einem vorzeichenlosen
  `cmp`) und nimmt `st0` herunter.
- Ein Programm muss den Stapel so hinterlassen, wie es ihn vorgefunden hat (leer): Windows und die C-Laufzeit erwarten
  das.
- 64-Bit-Programme rechnen mit Gleitkomma über SSE (die Register `xmm`, siehe `sse`); die x87 gibt es trotzdem.
- Der Assembler kennt keine Gleitkommazahlen in Daten (`dq 1.5`): Schreib die Bits (`dq 0x3FF8000000000000` ist 1,5)
  oder lade eine ganze Zahl mit `fild`.

F1 auf einem x87-Befehl zeigt zuerst seinen eigenen Abschnitt, dann diesen.

Verwandt: `sse`, `wait`

## sse, xmm – Gleitkomma und Vektoren in den xmm-Registern (SSE)

SSE bringt 8 Register `xmm0` bis `xmm7` (im 64-Bit-Code 16: bis `xmm15`) mit 128 Bit. Ein Befehl rechnet mit einem Wert
oder mit allen auf einmal, und sein Name sagt, wie:

| Endung | Bedeutung | Beispiel |
|---|---|---|
| `ss` | **s**calar **s**ingle: ein float (32 Bit) im unteren Teil | `addss xmm0, xmm1` |
| `sd` | **s**calar **d**ouble: ein double (64 Bit) | `addsd xmm0, xmm1` |
| `ps` | **p**acked **s**ingle: vier floats auf einmal | `addps xmm0, xmm1` |
| `pd` | **p**acked **d**ouble: zwei doubles auf einmal | `addpd xmm0, xmm1` |
| `p…` vorn | gepackte ganze Zahlen: Bytes, Wörter, Doppelwörter (`paddb`, `paddd`, `pcmpeqb` …) | `paddd xmm0, xmm1` |

```asm
  cvtsi2sd  xmm0, eax       ; xmm0 = eax als double
  addsd     xmm0, xmm0      ; verdoppelt
  cvttsd2si eax, xmm0       ; zurück zur ganzen Zahl (abgeschnitten)
  movss     xmm1, [f]       ; ein float aus dem Speicher
  mulss     xmm1, xmm1      ; zum Quadrat
  movss     [f], xmm1
  movups    xmm4, [v]       ; 16 Bytes, beliebige Adresse (movaps: durch 16 teilbar)
```

- `cvt…` wandelt um: `cvtsi2sd` ganze Zahl in double, `cvttsd2si` double in ganze Zahl (das zusätzliche `t`:
  abgeschnitten statt gerundet).
- Das 64-Bit-Windows übergibt Gleitkomma-Argumente in `xmm0` .. `xmm3` und gibt das Ergebnis in `xmm0` zurück.
- `movsd xmm0, [x]` (ein double laden) geht mit `.arch x64`; mit `.arch i386` kennt der Assembler `movsd` bisher nur
  als String-Befehl. AVX (die `vaddps` mit `ymm`) kennt der Assembler nicht.

F1 auf einem Befehl mit einem xmm-Register zeigt zuerst seinen eigenen Abschnitt, dann diesen.

Verwandt: `x87`, `x64`

## lgdt, lidt, sgdt, sidt – Deskriptortabellen

Laden (`lgdt`, `lidt`) oder speichern (`sgdt`, `sidt`) Adresse und Größe der globalen Deskriptortabelle (GDT) bzw. der Interrupt-Tabelle (IDT). Die Tabellen beschreiben die Segmente und die Interrupt-Routinen im Protected Mode.

Laden darf nur das Betriebssystem (Ring 0); `sgdt`/`sidt` sind auch in Programmen erlaubt.

**Flags:** keine

Verwandt: `lldt`, `ltr`, `lmsw`

## lldt, sldt, ltr, str – LDT und Task-Register

- `lldt`/`sldt`: lokale Deskriptortabelle laden / den Selektor lesen
- `ltr`/`str`: Task-Register laden / lesen (Task State Segment)

Laden nur im Betriebssystem (Ring 0).

**Flags:** keine

Verwandt: `lgdt`, `lar`

## smsw, lmsw, clts – Maschinenstatus

- `smsw`: das Maschinenstatuswort lesen (die unteren 16 Bit von CR0)
- `lmsw`: es setzen (z. B. das Bit für den Protected Mode)
- `clts`: das Task-Switched-Flag in CR0 löschen

`lmsw` und `clts` nur im Betriebssystem (Ring 0).

**Flags:** keine

Verwandt: `lgdt`

## lar, lsl, verr, verw, arpl – Selektoren prüfen

Befehle des Protected Mode, die einen Segment-Selektor untersuchen:

- `lar`: die Zugriffsrechte des Segments lesen
- `lsl`: seine Grenze (Größe) lesen
- `verr`, `verw`: ist es lesbar / schreibbar? (ZF = 1: ja)
- `arpl`: die Privilegstufe eines Selektors anpassen

**Flags:** ZF (Ergebnis der Prüfung)

Verwandt: `lldt`, `lgdt`

## !label

**Label** (Sprungmarke): ein Name für eine Adresse. Sprünge, Aufrufe und Daten beziehen sich darauf.

Dismonite vergibt automatische Namen wie `C00401020` (ein `call` zeigt darauf), `J00401020` (ein Sprung) oder `L00401020` (nur Daten); mit **N** gibt man einem Label einen eigenen Namen, Strg+Klick auf einen Namen (oder die Taste **F** in der Zeile) springt hin.
