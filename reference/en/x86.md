# x86 instructions (i386)

The instruction info of Dismonite (F1) shows the section for the instruction of the current row.
Each section starts with `## ` and the names it explains.

## mov – copy a value

Copies the source to the destination. The source stays unchanged.

**Syntax:** `mov dest, src`

- Destination: register or memory
- Source: register, memory or number (immediate)
- Not allowed: memory to memory; that needs a register.

**Flags:** none

```asm
mov eax, 5       ; eax = 5
mov ebx, eax     ; ebx = eax
mov [number], eax ; write
mov ecx, [number] ; read
```

Square brackets mean "the memory at this address"; without brackets the address itself is meant.

Related: `lea`, `xchg`, `push`

## push – put on the stack

Puts a value on top of the stack: `esp` becomes 4 smaller (16 bit: `sp` by 2), then the value is written to `[esp]`.

**Syntax:** `push src`

- Source: register, memory or number

**Flags:** none

```asm
push 0           ; parameter
call [ExitProcess]
```

Under Windows (stdcall/cdecl) the parameters of a function are passed with `push` from right to left; the first parameter is pushed last.

Related: `pop`, `call`

## pop – take from the stack

Takes the top value from the stack: it is read from `[esp]`, then `esp` becomes 4 larger (16 bit: `sp` by 2).

**Syntax:** `pop dest`

- Destination: register or memory

**Flags:** none

```asm
push ebx         ; save ebx
; ... use ebx ...
pop ebx          ; get it back
```

Related: `push`, `ret`

## call – call a subroutine

Puts the address of the next instruction (the return address) on the stack and jumps to the target. The subroutine returns there with `ret`.

**Syntax:** `call target`

- Target: label, register or memory (indirect)

**Flags:** none

```asm
call output        ; direct
call [ExitProcess] ; through the IAT
call eax           ; in eax
```

`call [ExitProcess]` is the usual call of a Windows function: Windows writes the address of the function into the import table (IAT) when it loads the program.

Related: `ret`, `jmp`, `push`

## ret, retn, retf – return from a subroutine

Takes the return address from the stack and jumps there, that is, behind the `call`.

**Syntax:** `ret` or `ret number`

- With a number: afterwards also removes that many bytes from the stack, e.g. the parameters (stdcall).
- `retf`: return from a far call (16 bit: segment and offset).

**Flags:** none

```asm
square:
    mov eax, [esp+4] ; parameter
    imul eax, eax
    ret 4    ; remove 4 bytes
```

Related: `call`, `pop`

## add – add

Adds the source to the destination: `dest = dest + src`.

**Syntax:** `add dest, src`

- Destination: register or memory
- Source: register, memory or number (not both memory)

**Flags:** OF, SF, ZF, AF, CF, PF according to the result

```asm
add eax, 10      ; eax = eax + 10
add esp, 8       ; remove 2 parameters
```

Related: `sub`, `inc`, `adc`

## inc – increase by 1

Increases the destination by 1: `dest = dest + 1`.

**Syntax:** `inc dest`

- Destination: register or memory

**Flags:** OF, SF, ZF, AF, PF; **CF stays unchanged** (unlike `add dest, 1`)

```asm
inc ecx          ; counter + 1
```

Related: `dec`, `add`

## dec – decrease by 1

Decreases the destination by 1: `dest = dest - 1`.

**Syntax:** `dec dest`

- Destination: register or memory

**Flags:** OF, SF, ZF, AF, PF; **CF stays unchanged**

```asm
again:
    ; ...
    dec ecx
    jnz again    ; until ecx = 0
```

Related: `inc`, `sub`, `loop`, `jnz`

## xor – exclusive or

Combines destination and source bit by bit: a bit of the result is 1 if exactly one of the two bits is 1.

**Syntax:** `xor dest, src`

- Destination: register or memory
- Source: register, memory or number

**Flags:** OF = 0, CF = 0; SF, ZF, PF according to the result

```asm
xor eax, eax     ; eax = 0
xor al, 0x20     ; flip bit 5
```

Related: `and`, `or`, `not`

## cmp – compare

Compares two values: calculates `dest - src`, but does not store the result, it only sets the flags. A conditional jump then decides.

**Syntax:** `cmp dest, src`

- Destination: register or memory
- Source: register, memory or number

**Flags:** OF, SF, ZF, AF, CF, PF as for `sub`

```asm
cmp eax, 10
jz ten           ; if eax = 10
jb smaller       ; if eax < 10
```

Related: `test`, `sub`, conditional jumps (`jz`, `jnz`, ...)

## jcc – conditional jumps
<!-- names: jz, je, jnz, jne, jc, jb, jnae, jnc, jae, jnb, ja, jnbe, jbe, jna, jl, jnge, jge, jnl, jg, jnle, jle, jng, js, jns, jo, jno, jp, jpe, jnp, jpo -->

Jump to the target if the condition is met; otherwise execution goes on with the next instruction. The condition checks the flags, usually after `cmp`, `test` or a calculation.

**Syntax:** `jcc target` (target: label)

After `cmp a, b`:

- `jz`/`je`: a = b (ZF = 1); `jnz`/`jne`: a not equal b (ZF = 0)
- unsigned: `jb`/`jc` a < b (CF = 1), `jae`/`jnc` a >= b, `ja` a > b, `jbe` a <= b
- signed: `jl` a < b, `jge` a >= b, `jg` a > b, `jle` a <= b
- `js`/`jns`: result negative / not negative; `jo`/`jno`: overflow / none; `jp`/`jnp`: parity

Several names are the same instruction, e.g. `jz` and `je`; Dismonite writes the form with `z`.

**Flags:** none changed, only read

```asm
    mov ecx, 5
again:
    ; ...
    dec ecx
    jnz again    ; until ecx = 0
```

Related: `cmp`, `test`, `jmp`, `loop`

## jmp – jump

Always jumps to the target.

**Syntax:** `jmp target`

- Target: label, register or memory (indirect)

**Flags:** none

```asm
jmp done            ; direct
jmp [table+eax*4]   ; table
```

Related: conditional jumps (`jz`, ...), `call`

## nop – do nothing

Does nothing except go on to the next instruction. Serves as a filler byte, e.g. so that a function starts at a round address.

**Syntax:** `nop`

**Flags:** none

Code: `90`

## db, dw, dd, dq – data

Puts bytes into the file: `db` one byte each, `dw` a word (2 bytes), `dd` a double word (4 bytes), `dq` 8 bytes. Several values separated by commas; with `db` also text in quotes. With `dw 0x5A4D` the bytes `4D 5A` are in the file: x86 stores the low byte first (little endian).

**Syntax:** `db value, ...`

```asm
db 'Hello',13,10,0  ; text
dw 0x5A4D           ; 'MZ'
dd 0x00401000
```

In Dismonite, lines with `db`/`dw`/`dd` are data: bytes that are not read as an instruction. In the structures of the file format (PE header etc.) the comment holds the name of the field.

Related: `rva`, `org`, `align`

## resb, resw, resd, resq – reserve space

Reserves memory without file bytes (uninitialised data, `.bss`): `resb` bytes, `resw` words, `resd` dwords, `resq` qwords; the number says how many. The Windows loader fills the space with zeros at start, nothing of it is in the file. In the assembler (`.format pe`) `resb` may stand at the end of a section.

**Syntax:** `resb count`

```asm
buffer: resb 4096   ; 4096 bytes
count:  resd 1      ; one dword
```

In Dismonite these are the rows in the memory behind the file (labels `V...`); B, W, D, Q set how large a variable is.

Related: `db`, `align`

## func – a function with a stack frame

Writes the stack frame of a function for you: `push ebp / mov ebp, esp / sub esp, n` at `begin`, the matching epilog at `end` and at every plain `ret` inside. The parameters and local variables have names, the assembler replaces them by `[ebp+x]`. Only for `.arch i386`.

**Syntax:**

```asm
func DoStuff(count, flags:word) cdecl uses ebx, esi
  var temp, buffer:16, small:byte
begin
  mov eax, count        ; mov eax, dword [ebp+8]
  mov temp, eax         ; mov dword [ebp-4], eax
  lea edx, buffer       ; lea edx, [ebp-20]
  mov [buffer+4], eax   ; mov [ebp-16], eax
end
```

- `func Name(p1, p2:type)` is also a label `Name:`. Parameters are dword slots at `[ebp+8]`, `[ebp+12]` ...; a type (`byte`, `word`, `dword`) only sets the size of the access. Default convention is `stdcall` (`ret 4*n` removes the arguments); `cdecl` ends with a plain `ret`.
- `var name, name:type, name:N` declares locals below ebp: a dword, a byte/word/dword (each takes 4 bytes) or an array of N bytes. A variable stands for `size [ebp+x]`; an array name for its address (`[buf+eax*4]`, `buf+4` work, a variable in `[...]` is an error).
- `uses ebx, esi` saves registers behind the locals and restores them before the epilog.
- `ret` alone inside the function is the epilog (early return); `end` adds an epilog unless the last statement is `ret`.
- **Calls with arguments:** `call Add2(7, 5)` pushes the arguments from right to left and calls; for a `cdecl` func it adds `add esp, 4*n` afterwards. A declared func gives its own convention and its number of parameters (a wrong count is an error); any other label is `stdcall`, write `call cdecl name(...)` for cdecl. An import has the convention of its `.import` line, `stdcall` unless the line says `cdecl`: `.import msvcrt.dll cdecl printf, scanf` (then `call [printf](fmt, 42)` adds `add esp, 8`), `.import user32.dll MessageBoxA` (stdcall). For a C runtime dll (`msvcrt.dll`, `ucrtbase.dll`, `api-ms-win-crt-*`) the word is required: a call with arguments without it is an error. `call cdecl [name](...)` or `call stdcall [name](...)` decides for one call. An argument is a register, a number, a label (its address), a parameter or local (a dword: its value; byte/word: zero extended; an array: its address), `&name` (the address of a local) or `[ebx+4]`. For an address or a byte/word the assembler uses the first of `eax`, `ecx`, `edx` that the argument list does not name (an error if all three are named); `esp` is not allowed in an argument. The result stays in `eax`.
- **`if` / `else` / `endif`** (anywhere in i386 code, also in a func, nested): `if [signed|unsigned] a op b` is `cmp a, b` and the jump of the opposite condition around the block; `else` adds a `jmp` over the second block. `a` and `b` are operands (in a func its names work), **no expressions**: one comparison, `==`, `!=`, `<`, `<=`, `>`, `>=`. `==` and `!=` need no word; the other four say **`signed`** (`jge`, `jg`, `jle`, `jl` skip the block) or **`unsigned`** (`jae`, `ja`, `jbe`, `jb`); without the word it is an error, unless **`.compare signed`** or **`.compare unsigned`** stands in front of it (the word for all ifs behind it, until the next `.compare`; `.compare none` takes it back); a word in the `if` line always wins. Memory against a number needs the size: `if dword [x] == 5`. **`if a & b`** is `test a, b` and `jz` around the block (it runs if a bit is set in both), `if a & b == 0` is `test` and `jnz`, `if a & b != 0` is the same as `if a & b`; no `signed` / `unsigned` there, nothing else behind it. The generated labels are `asmogen_if<line>e` and `x`. **`if zero`**, `if not carry`, `if below or equal` ... name the condition by a flag word: no `cmp`, only the jump around the block (the flags of the instruction in front count); words `zero` (`equal`), `carry`, `sign`, `overflow`, `parity`, `above` / `below` (unsigned), `less` / `greater` (signed), `not` in front, `or equal` behind above / below / less / greater. **`do` ... `while <condition>`** runs the block once and then as long as the condition holds (the forms of the `if`; the jump back is the condition itself: `while not zero` is `jnz`); `do` and `while` cannot name a func, a parameter or a local; example `examples/func/func_loop.asm`. Example: `examples/func/func_if.asm`.
- Names must not be registers, instructions or keywords. The errors show the line of the source.

Related: `call`, `ret`, `push`

## rva – relative address

Writes the address of a label as an RVA (relative virtual address): the address in memory minus the base address of the program (`.imagebase`). It is a double word (4 bytes).

**Syntax:** `rva label`

```asm
rva start  ; start - imagebase
```

PE files give addresses almost everywhere as RVAs, so that Windows can also load the program at a different base.

Related: `dd`, `org`

## org – set the position

Sets the position in the file: the following bytes start at this offset. Up to there it is filled with zeros.

**Syntax:** `org offset`

```asm
org 0x3C   ; offset of e_lfanew
dd 0x00000080
```

Dismonite writes `org` where only zeros stand in front of a structure; the zeros then do not appear as rows of their own.

Related: `align`, `db`

## align – fill up to a boundary

Fills with zeros until the position is divisible by the number. In PE files, each section starts at a multiple of `FileAlignment` this way.

**Syntax:** `align number`

```asm
align 0x200 ; FileAlignment 512
```

Related: `org`

## sub – subtract

Subtracts the source from the destination: `dest = dest - src`.

**Syntax:** `sub dest, src`

- Destination: register or memory
- Source: register, memory or number (not both memory)

**Flags:** OF, SF, ZF, AF, CF, PF according to the result; CF = 1 if unsigned a "borrow" was needed (source larger than destination)

```asm
sub eax, 4       ; eax = eax - 4
sub esp, 0x20    ; room for
                 ; local values
```

Related: `add`, `sbb`, `dec`, `cmp`, `neg`

## adc – add with carry

Adds source and carry flag to the destination: `dest = dest + src + CF`. This adds numbers larger than a register: first the lower parts with `add`, then the upper parts with `adc`.

**Syntax:** `adc dest, src`

**Flags:** OF, SF, ZF, AF, CF, PF according to the result

```asm
add eax, ebx  ; lower 32 bits
adc edx, ecx  ; upper + CF
```

Related: `add`, `sbb`, `clc`, `stc`

## sbb – subtract with borrow

Subtracts source and carry flag from the destination: `dest = dest - src - CF`. The counterpart of `adc` for large numbers.

**Syntax:** `sbb dest, src`

**Flags:** OF, SF, ZF, AF, CF, PF according to the result

```asm
sub eax, ebx  ; lower 32 bits
sbb edx, ecx  ; upper - CF
sbb eax, eax  ; 0 or -1
```

The trick `sbb eax, eax` turns the carry flag into a mask: 0 if CF = 0, else -1 (all bits 1).

Related: `sub`, `adc`

## and – and

Combines destination and source bit by bit: a bit of the result is 1 only if both bits are 1. Used to clear bits (mask).

**Syntax:** `and dest, src`

**Flags:** OF = 0, CF = 0; SF, ZF, PF according to the result

```asm
and eax, 0xFF ; lowest byte
and esp, -16  ; round down to 16
```

Related: `or`, `xor`, `not`, `test`

## or – or

Combines destination and source bit by bit: a bit of the result is 1 if at least one of the two bits is 1. Used to set bits.

**Syntax:** `or dest, src`

**Flags:** OF = 0, CF = 0; SF, ZF, PF according to the result

```asm
or eax, 0x80  ; set bit 7
or eax, eax   ; ZF=1 if eax=0
```

`or eax, eax` (or `test eax, eax`) checks a register for 0 without changing it.

Related: `and`, `xor`, `test`

## not – invert bits

Inverts every bit of the destination (one's complement): 0 becomes 1 and 1 becomes 0.

**Syntax:** `not dest`

- Destination: register or memory

**Flags:** none

```asm
not eax          ; eax = -eax - 1
```

Related: `neg`, `xor`, `and`

## neg – negate

Turns the destination into its negative number (two's complement): `dest = 0 - dest`.

**Syntax:** `neg dest`

**Flags:** CF = 0 if the destination was 0, else 1; OF, SF, ZF, AF, PF according to the result

```asm
neg eax          ; 5 becomes -5
```

Related: `not`, `sub`

## test – test bits

Combines destination and source like `and`, but does not store the result, it only sets the flags. A conditional jump then decides.

**Syntax:** `test dest, src`

**Flags:** OF = 0, CF = 0; SF, ZF, PF according to the result

```asm
test eax, eax
jz zero       ; if eax = 0
test al, 1
jnz odd       ; bit 0 set
```

Related: `cmp`, `and`, conditional jumps (`jz`, ...)

## mul – multiply unsigned

Multiplies the accumulator by the operand. The result is twice as wide:

- 8 bit: `ax = al * src`
- 16 bit: `dx:ax = ax * src`
- 32 bit: `edx:eax = eax * src`

**Syntax:** `mul src` (register or memory, no number)

**Flags:** CF = OF = 1 if the upper half of the result is not 0; SF, ZF, AF, PF undefined

```asm
mov eax, 1000
mul ecx       ; edx:eax=eax*ecx
```

Related: `imul`, `div`

## imul – multiply signed

Multiplies signed numbers. Three forms:

- `imul src`: like `mul`, result in `edx:eax` (16 bit: `dx:ax`)
- `imul dest, src`: `dest = dest * src`
- `imul dest, src, number`: `dest = src * number`

With the forms that have a destination only the lower half is kept.

**Flags:** CF = OF = 1 if the result does not fit into the destination

```asm
imul eax, ecx     ; eax*=ecx
imul eax, [esi],12 ; *12
```

Related: `mul`, `idiv`

## div – divide unsigned

Divides the double-wide accumulator by the operand; quotient and remainder:

- 8 bit: `ax / src`, quotient `al`, remainder `ah`
- 16 bit: `dx:ax / src`, quotient `ax`, remainder `dx`
- 32 bit: `edx:eax / src`, quotient `eax`, remainder `edx`

**Syntax:** `div src` (register or memory)

Dividing by 0 or a quotient that does not fit raises an exception (interrupt 0). So set `edx` to 0 first.

**Flags:** undefined

```asm
xor edx, edx     ; upper half 0
mov ecx, 10
div ecx          ; eax = eax/10,
                 ; edx = remainder
```

Related: `idiv`, `mul`, `cdq`

## idiv – divide signed

Like `div`, but signed. Before it, the accumulator is extended to double width with sign by `cdq` (16 bit: `cwd`, 8 bit: `cbw`).

**Syntax:** `idiv src`

The remainder has the sign of the dividend: -7 / 2 gives -3, remainder -1.

**Flags:** undefined

```asm
cdq           ; edx = sign
idiv ecx      ; edx:eax / ecx
```

Related: `div`, `imul`, `cdq`, `cwd`

## lea – calculate an address

Calculates the address of the memory operand and writes it to the destination. Nothing is read from memory. Because the address calculation can add registers and multiply by 2, 4 or 8, `lea` also serves as a fast calculation.

**Syntax:** `lea dest, [address]` (destination: register)

**Flags:** none

```asm
lea esi, [text]   ; esi = address
lea eax, [ebx+ecx*4+8]
lea eax, [eax+eax*2] ; eax*3
```

Related: `mov`

## xchg – exchange

Exchanges the values of destination and source. With a memory operand this is atomic (as with `lock`), for locks between threads.

**Syntax:** `xchg dest, src` (at least one register)

**Flags:** none

```asm
xchg eax, ebx
xchg eax, eax    ; = nop (90)
```

Related: `mov`, `lock`

## movzx – copy zero-extended

Copies a byte or word into a larger register and fills the upper bits with 0 (unsigned).

**Syntax:** `movzx dest, src` (destination: register 16/32 bit; source: 8 or 16 bit)

**Flags:** none

```asm
movzx eax, byte [esi] ; 0..255
movzx ecx, ax
```

Related: `movsx`, `mov`

## movsx – copy sign-extended

Copies a byte or word into a larger register and fills the upper bits with the sign bit: -1 stays -1.

**Syntax:** `movsx dest, src`

**Flags:** none

```asm
movsx eax, byte [esi] ; -128..127
```

Related: `movzx`, `cbw`, `cwde`

## cbw, cwde – extend the accumulator with sign

Extends the accumulator to double width, with sign:

- `cbw`: `al` to `ax` (16 bit)
- `cwde`: `ax` to `eax` (32 bit)

It is the same code (98); which name applies depends on the operand size.

**Flags:** none

Related: `cwd`, `cdq`, `movsx`

## cwd, cdq – prepare for signed division

Fills the register above with the sign of the accumulator:

- `cwd`: `dx:ax` from `ax` (16 bit)
- `cdq`: `edx:eax` from `eax` (32 bit)

After it, `idiv` can divide. Code 99, name by operand size.

**Flags:** none

```asm
mov eax, -7
cdq              ; edx = -1
idiv ecx
```

Related: `idiv`, `cbw`, `cwde`

## shl, sal – shift left

Shifts the bits of the destination to the left; zeros come in on the right. Each place doubles the value. `shl` and `sal` are the same instruction.

**Syntax:** `shl dest, count` (count: 1, number or `cl`)

**Flags:** CF = the bit shifted out last; SF, ZF, PF according to the result; OF defined only for 1 place

```asm
shl eax, 2       ; eax * 4
shl edx, cl
```

Related: `shr`, `sar`, `rol`, `shld`

## shr – shift right (unsigned)

Shifts the bits to the right; zeros come in on the left. Each place halves the unsigned value (rounded down).

**Syntax:** `shr dest, count`

**Flags:** CF = the bit shifted out last; SF, ZF, PF according to the result

```asm
shr eax, 4       ; eax / 16
```

Related: `sar`, `shl`, `shrd`

## sar – shift right (signed)

Shifts to the right; the sign bit is repeated on the left. This halves a signed number (rounded toward minus infinity: -7 sar 1 is -4).

**Syntax:** `sar dest, count`

**Flags:** CF = the bit shifted out last; SF, ZF, PF according to the result

```asm
sar eax, 31      ; 0 or -1
```

Related: `shr`, `idiv`

## rol, ror – rotate

Shifts the bits in a circle: what goes out on one side comes back in on the other. `rol` to the left, `ror` to the right.

**Syntax:** `rol dest, count`

**Flags:** CF = the bit that went around; OF only for 1 place; the others stay

```asm
rol eax, 8       ; turn the bytes
ror ax, 8        ; = xchg al, ah
```

Related: `rcl`, `rcr`, `shl`

## rcl, rcr – rotate through the carry flag

Like `rol`/`ror`, but the carry flag is part of the circle: the bit that goes out goes to CF, the old value of CF comes in. This shifts numbers across several registers.

**Syntax:** `rcl dest, count`

**Flags:** CF; OF only for 1 place

```asm
shl eax, 1       ; bit 31 -> CF
rcl edx, 1       ; CF -> bit 0
```

Related: `rol`, `ror`, `shld`

## shld, shrd – double shift

Shifts the destination and fills the freed bits from a second register (which itself stays unchanged). This shifts 64-bit values held in two registers.

**Syntax:** `shld dest, src, count` (count: number or `cl`)

**Flags:** CF = the bit shifted out last; SF, ZF, PF according to the result

```asm
shld edx, eax, 4 ; edx:eax << 4
shl eax, 4
```

Related: `shl`, `shr`

## bt, bts, btr, btc – test a single bit

Copies one bit of the destination into the carry flag:

- `bt`: only test
- `bts`: then set (1)
- `btr`: then clear (0)
- `btc`: then invert

**Syntax:** `bt dest, number` (number: register or number)

**Flags:** CF = the old bit

```asm
bt eax, 5
jc is_set        ; if bit 5 = 1
```

Related: `test`, `and`, `or`

## bsf, bsr – find a bit

Finds the first set bit of the source and writes its number to the destination: `bsf` from the lowest bit, `bsr` from the highest.

**Syntax:** `bsf dest, src`

**Flags:** ZF = 1 if the source is 0 (then the destination is undefined)

```asm
bsr ecx, eax     ; highest bit
jz zero
```

Related: `bt`, `test`

## setcc – set a byte by condition
<!-- names: setz, sete, setnz, setne, setc, setb, setnae, setnc, setae, setnb, seta, setnbe, setbe, setna, setl, setnge, setge, setnl, setg, setnle, setle, setng, sets, setns, seto, setno, setp, setpe, setnp, setpo -->

Writes 1 into a byte if the condition is met, else 0. The conditions are the same as for the conditional jumps (`setz` like `jz` etc.).

**Syntax:** `setcc dest` (destination: 8-bit register or byte in memory)

**Flags:** none changed, only read

```asm
cmp eax, ebx
setz al        ; 1 if equal
movzx eax, al  ; as 32 bit
```

Related: conditional jumps (`jz`, ...), `cmp`, `test`

## cmovcc – copy by condition
<!-- names: cmovz, cmove, cmovnz, cmovne, cmovc, cmovb, cmovnae, cmovnc, cmovae, cmovnb, cmova, cmovnbe, cmovbe, cmovna, cmovl, cmovnge, cmovge, cmovnl, cmovg, cmovnle, cmovle, cmovng, cmovs, cmovns, cmovo, cmovno, cmovp, cmovpe, cmovnp, cmovpo -->

Copies the source to the destination only if the condition is met, else nothing happens. It replaces a short conditional jump: there is no jump to guess. The conditions are the same as for the conditional jumps (`cmovz` like `jz` etc.). Since the Pentium Pro. A memory source is read even if the condition is not met.

**Syntax:** `cmovcc dest, src` (destination: register, source: register or memory)

**Flags:** none changed, only read

```asm
cmp eax, ebx
cmovl eax, ebx    ; eax = the larger of both (signed)
```

Related: conditional jumps (`jz`, ...), `setcc`, `cmp`, `mov`

## bswap – reverse the byte order

Reverses the order of the four bytes of a 32-bit register: `0x11223344` becomes `0x44332211`. This converts between little endian (x86) and big endian (network byte order, many file formats). Since the 486. Only 32-bit registers; for a 16-bit value use `xchg al, ah` or `ror ax, 8`.

**Syntax:** `bswap reg32`

**Flags:** none

```asm
mov eax, 0x11223344
bswap eax         ; eax = 0x44332211
```

Related: `xchg`, `ror`, `rol`

## xadd – exchange and add

Adds the source to the destination and puts the old value of the destination into the source. With `lock` this is an atomic "fetch and add": counters that several threads use. Since the 486.

**Syntax:** `xadd dest, src` (destination: register or memory, source: register)

**Flags:** as `add`

```asm
mov eax, 1
lock xadd [counter], eax   ; counter + 1, eax = the old value
```

Related: `add`, `xchg`, `lock`, `cmpxchg`

## cmpxchg, cmpxchg8b – compare and exchange

`cmpxchg` compares the accumulator (`al`, `ax`, `eax`) with the destination. Equal: the source is written to the destination and ZF = 1. Not equal: the destination is loaded into the accumulator and ZF = 0. With `lock` it is atomic: the base of spin locks and lock-free data structures. `cmpxchg8b` does the same for 64 bit with `edx:eax` (expected) and `ecx:ebx` (new). Since the 486 (`cmpxchg8b`: Pentium).

**Syntax:** `cmpxchg dest, src` (destination: register or memory, source: register); `cmpxchg8b mem64`

**Flags:** ZF as described; `cmpxchg` sets the others like `cmp`, `cmpxchg8b` only ZF

```asm
xor eax, eax                ; expected: 0, the lock is free
mov ecx, 1                  ; new value: taken
lock cmpxchg [lockvar], ecx
jnz busy                    ; ZF = 0: somebody else has it
```

Related: `xchg`, `xadd`, `lock`, `pause`

## cpuid – ask for the processor

Returns information about the processor in `eax`, `ebx`, `ecx` and `edx`; the function number is in `eax` (for some functions also in `ecx`). Function 0 gives the highest function number and the vendor name in `ebx`, `edx`, `ecx` (`GenuineIntel`, `AuthenticAMD`), function 1 the model and the feature bits (SSE, ...), `0x80000000` and up the extended functions. Overwrites `eax`, `ebx`, `ecx` and `edx`.

**Syntax:** `cpuid`

**Flags:** none

```asm
xor eax, eax
cpuid             ; eax = highest function, ebx, edx, ecx = vendor name
```

Related: `rdtsc`

## rdtsc – read the time stamp counter

Reads the 64-bit counter of processor cycles into `edx:eax` (high part in `edx`). Good to measure short times; the counter keeps running while the program waits or another program runs, and the cores of a processor may differ. Since the Pentium.

**Syntax:** `rdtsc`

**Flags:** none

```asm
rdtsc
mov esi, eax      ; low part: the start
; ... the code to measure ...
rdtsc
sub eax, esi      ; cycles
```

Related: `cpuid`

## pause – hint in a waiting loop

A hint to the processor in a loop that waits for a value to change: it saves power and avoids a slowdown when the loop ends. It is encoded as `rep nop` (`F3 90`), so older processors just execute a `nop`. Since the Pentium 4.

**Syntax:** `pause`

**Flags:** none

```asm
spin:
  pause
  cmp dword [flag], 0
  jz spin
```

Related: `nop`, `lock`, `cmpxchg`

## ud2 – undefined instruction

Always raises the exception "invalid instruction" (`0F 0B`): the program is ended, a debugger stops there. Used for places that must never be reached, e.g. behind a call that does not return.

**Syntax:** `ud2`

**Flags:** none

Related: `int3`, `hlt`, `int`

## int3 – breakpoint

A one-byte interrupt (`CC`) that raises the exception "breakpoint". Debuggers put it over the first byte of an instruction to stop there. Without a debugger the program ends. Compilers and Windows also use `CC` as padding between functions, so a long run of `int3` in a disassembly is just filler. The assembler of Asmonite does not know the name `int3`, write `int 3`.

**Syntax:** `int3`

**Flags:** none

Related: `int`, `ud2`, `hlt`

## sysenter, sysexit – fast system call

`sysenter` jumps into the kernel without the slow interrupt gate; Windows and Linux use it in their system call stubs (the function number is in `eax`). `sysexit` returns to the program and is only allowed in kernel mode. You see `sysenter` in `ntdll.dll`, not in normal programs. 64-bit programs use `syscall` for the same job.

**Syntax:** `sysenter`, `sysexit`

**Flags:** changed by the system call

Related: `int`, `iret`

## popcnt, lzcnt, tzcnt – count bits

`popcnt` counts the set bits of the source, `lzcnt` the zero bits above the highest set bit (leading zeros), `tzcnt` the zero bits below the lowest set bit (trailing zeros). `lzcnt` and `tzcnt` are encoded as `rep bsr` and `rep bsf`: a processor without them executes `bsr` and `bsf`, which give another result (the bit number, not the count).

**Syntax:** `popcnt dest, src` (dest: register, src: register or memory); the same for `lzcnt` and `tzcnt`

**Flags:** `popcnt`: ZF = 1 if the source is 0, the others are cleared. `lzcnt`, `tzcnt`: CF = 1 if the source is 0, ZF = 1 if the result is 0

```asm
popcnt ecx, eax    ; number of set bits in eax
tzcnt edx, eax     ; number of the lowest set bit (32 if eax = 0)
```

Related: `bsf`, `bsr`, `bt`

## movsxd – copy sign-extended (32 to 64 bit)

Copies a 32-bit value (register or memory) into a 64-bit register and fills the upper half with the sign bit. Only in 64-bit mode. A plain `mov eax, ...` does the opposite: it writes the lower half and clears the upper one, so a signed 32-bit value (a C `int`) that is used as a 64-bit number or index needs `movsxd`.

**Syntax:** `movsxd dest64, src32` (source: 32-bit register or memory)

**Flags:** none

```asm
movsxd rax, ecx           ; rax = (64 bit) ecx, with sign
movsxd rdx, dword [rbx+4]
```

Related: `movsx`, `movzx`, `cdqe`, `mov`

## cdqe, cqo – extend rax, prepare a 64-bit division

`cdqe` sign-extends `eax` to `rax` (as `cwde` does `ax` to `eax`). `cqo` fills `rdx` with the sign of `rax`: `rdx:rax` is then the 128-bit number for a signed 64-bit division with `idiv`. The 32-bit forms are `cwde` and `cdq`.

**Syntax:** `cdqe`, `cqo`

**Flags:** none

```asm
mov rax, [number]
cqo               ; rdx:rax = rax with sign
idiv rcx          ; rax = quotient, rdx = remainder
```

Related: `cbw`, `cwde`, `cwd`, `cdq`, `idiv`, `movsxd`

## syscall, sysret – system call (64 bit)

`syscall` enters the kernel; it is the 64-bit counterpart of `sysenter`. On Windows the number of the service is in `eax`, the first argument in `r10` (copied from `rcx`), the next ones in `rdx`, `r8`, `r9` and on the stack; every function of `ntdll.dll` that reaches the kernel ends in the stub `mov r10, rcx` / `mov eax, N` / `syscall` / `ret`. On Linux the number is in `rax` and the arguments are in `rdi`, `rsi`, `rdx`, `r10`, `r8`, `r9`. The processor stores the return address in `rcx` and the flags in `r11`, so both are overwritten. `sysret` returns and is only allowed in kernel mode. Programs call the API, not `syscall`.

**Syntax:** `syscall`, `sysret`

**Flags:** the flags go to `r11`; `sysret` restores them

```asm
mov r10, rcx      ; the first argument
mov eax, 0x26     ; number of the service (differs between versions of Windows)
syscall
ret
```

Related: `sysenter`, `int`, `call`

## rip – addressing relative to the instruction pointer

In 64-bit mode memory can be addressed as a distance from the next instruction: `[rip+0x1234]` (Asmonite's assembler writes `[rel label]`, the disassembler `[rip+...]`). The distance has 32 bits, so data within 2 GB of the code is reached without an absolute address. That is why programs can be loaded at another address each time (ASLR) without changing the code: `lea rax, [rip+x]` makes the address of data, `call [rip+x]` calls through the import address table. The `rip` of the address is the address of the **next** instruction.

**Syntax:** `[rip+disp32]`, in the assembler `[rel label]`

```asm
lea rcx, [rel msg]    ; address of the text, wherever the program is
call [rel printf]     ; through the import address table
```

Related: `lea`, `mov`, `call`, `x64`

## x64 – the 64-bit mode in short

**Registers:** 16 general registers `rax rbx rcx rdx rsi rdi rbp rsp r8 .. r15`. Parts: `eax`/`r8d` (32 bit), `ax`/`r8w` (16), `al`/`r8b` (8, new: `sil dil bpl spl`). **Writing a 32-bit part clears the upper half**; writing 16 or 8 bit leaves it. `ah`..`bh` cannot be used together with the new registers.

**REX prefix** (`0x40`..`0x4F`): its bits make the operand 64-bit (`W`) and address the registers 8..15 (`R`, `X`, `B`). `48 89 D8` is `mov rax, rbx`: the same code as 32 bit with one byte in front. Most constants are still 32 bit (sign-extended); only `mov r64, imm64` carries 64 bits.

**Gone:** `pusha`/`popa`, `les`/`lds`, `bound`, the BCD instructions (`aaa`, `daa`, ...), `into`; the one-byte `inc`/`dec` (the bytes became REX). `push` and `pop` work with 64 bits; `call`, `jmp`, `ret` are 64 bit.

**Calling convention (Windows):** the first four arguments in `rcx`, `rdx`, `r8`, `r9` (floating point in `xmm0`..`xmm3`), the rest on the stack; **the caller reserves 32 bytes of "shadow space"** above the return address; result in `rax` (`xmm0`); the stack is aligned to 16 at the call. Kept by the function: `rbx rbp rdi rsi rsp r12`..`r15`. Free to use: `rax rcx rdx r8`..`r11`.
**Linux (System V):** `rdi rsi rdx rcx r8 r9`, no shadow space, kept: `rbx rbp r12`..`r15`.

**Addresses:** `[rip+disp]` for data near the code, see `rip`.

Related: `rip`, `movsxd`, `cdqe`, `syscall`, `mov`

## pusha, pushad – all registers onto the stack

Puts the general registers on the stack in this order: `eax`, `ecx`, `edx`, `ebx`, `esp` (the value before the instruction), `ebp`, `esi`, `edi`. `pusha` is the 16-bit form (`ax` ... `di`).

**Flags:** none

Related: `popa`, `push`

## popa, popad – all registers from the stack

Gets back the registers that `pusha`/`pushad` put there (in reverse order). The saved value of `esp` is skipped.

**Flags:** none

```asm
pushad           ; save everything
; ...
popad            ; everything back
```

Related: `pusha`, `pop`

## pushf, pushfd – flags onto the stack

Puts the flag register on the stack: `pushf` 16 bit, `pushfd` 32 bit (EFLAGS).

**Flags:** none

```asm
pushf            ; save flags
cli              ; interrupts off
; ...
popf             ; as before
```

Related: `popf`, `lahf`

## popf, popfd – flags from the stack

Takes the flag register from the stack. Some flags (e.g. IF, IOPL) may only be changed by the operating system; in user mode they stay.

**Flags:** all from the stack

Related: `pushf`, `sahf`

## lahf, sahf – flags and ah

`lahf` copies SF, ZF, AF, PF and CF to `ah` (bits 7, 6, 4, 2, 0); `sahf` writes them back from `ah` into the flags.

**Flags:** `lahf` none; `sahf` SF, ZF, AF, PF, CF

Related: `pushf`, `popf`

## clc, stc, cmc – carry flag

- `clc`: CF = 0
- `stc`: CF = 1
- `cmc`: invert CF

Functions often report success or failure this way (DOS: CF = 1 after `int 21h` means error).

**Flags:** CF

```asm
int 0x21
jc error         ; CF = 1: error
```

Related: `adc`, `sbb`, `jc`

## cld, std – direction of the string instructions

The direction flag decides whether the string instructions (`movsb`, `stosb`, `lodsb`, ...) increase or decrease `esi`/`edi`:

- `cld`: DF = 0, upward (the normal case)
- `std`: DF = 1, downward

**Flags:** DF

```asm
cld
rep movsb      ; forward
```

Related: `movsb`, `stosb`, `rep`

## cli, sti – block and allow interrupts

- `cli`: IF = 0, hardware interrupts are not accepted
- `sti`: IF = 1, they are accepted again

Under DOS e.g. when changing an interrupt vector; under Windows not allowed in user mode (exception).

**Flags:** IF

Related: `pushf`, `popf`, `int`, `iret`

## loop – loop with a counter

Decreases `ecx` (16 bit: `cx`) by 1 and jumps to the target as long as the result is not 0.

**Syntax:** `loop target` (near, -128 to +127 bytes)

**Flags:** none (unlike `dec`)

```asm
    mov ecx, 10
again:
    ; ...
    loop again   ; 10 times
```

Related: `loope`, `loopne`, `jcxz`, `dec`, `jnz`

## loope, loopz, loopne, loopnz – loop with a counter and a condition

Like `loop`, but with a second condition:

- `loope`/`loopz`: go on as long as `ecx` is not 0 and ZF = 1
- `loopne`/`loopnz`: go on as long as `ecx` is not 0 and ZF = 0

**Flags:** none changed

```asm
search:
    lodsb
    cmp al, ' '
    loope search ; spaces
```

Related: `loop`, `repe`, `repne`

## jcxz, jecxz – jump if the counter is 0

Jumps if `cx` (`jcxz`) or `ecx` (`jecxz`) is 0. Typical before a loop with `loop`, so that it does not run at all with 0.

**Syntax:** `jecxz target` (near, -128 to +127 bytes)

**Flags:** none

```asm
jecxz finished
again:
    ; ...
    loop again
finished:
```

Related: `loop`, `jz`

## enter – build a stack frame

Builds the frame of a function: `push ebp`, `mov ebp, esp`, `sub esp, size`. The second number (nesting depth, usually 0) copies frame pointers of outer functions (Pascal).

**Syntax:** `enter size, depth`

**Flags:** none

```asm
enter 16, 0      ; 16 bytes local
; ...
leave
ret
```

Related: `leave`, `push`, `mov`

## leave – tear down a stack frame

Tears down the frame that `enter` (or `push ebp` / `mov ebp, esp`) built: `mov esp, ebp`, `pop ebp`. Usually `ret` follows.

**Flags:** none

```asm
push ebp
mov ebp, esp
sub esp, 8
; ...
leave
ret
```

Related: `enter`, `ret`

## movsb, movsw, movsd – copy memory (string)

Copies a byte (`movsb`), word (`movsw`) or double word (`movsd`) from `[esi]` to `[edi]` and moves both pointers on: by 1, 2 or 4, upward with DF = 0 (`cld`), downward with DF = 1. In 16-bit code `ds:si` and `es:di`.

With `rep` in front this is repeated `ecx` times: a whole block.

**Flags:** none

```asm
cld
mov esi, source
mov edi, dest
mov ecx, 100
rep movsb        ; 100 bytes
```

Related: `rep`, `stosb`, `lodsb`, `cld`

## stosb, stosw, stosd – fill memory (string)

Writes `al` (`stosb`), `ax` (`stosw`) or `eax` (`stosd`) to `[edi]` and moves `edi` on (direction by DF). With `rep` a block is filled. In 16-bit code `es:di`.

**Flags:** none

```asm
cld
xor eax, eax
mov ecx, 256
rep stosd        ; clear 1 KB
```

Related: `rep`, `movsb`, `lodsb`

## lodsb, lodsw, lodsd – load from memory (string)

Reads `[esi]` into `al` (`lodsb`), `ax` (`lodsw`) or `eax` (`lodsd`) and moves `esi` on. Typical in loops that read text character by character. In 16-bit code `ds:si`.

**Flags:** none

```asm
next:
    lodsb      ; al = [esi]
    test al, al
    jnz next     ; up to the 0
```

Related: `stosb`, `movsb`, `loop`

## cmpsb, cmpsw, cmpsd – compare memory (string)

Compares `[esi]` with `[edi]` (like `cmp`, only the flags) and moves both pointers on. With `repe` it compares as long as the values are equal; afterwards ZF shows whether everything was equal.

**Flags:** as `cmp`

```asm
mov ecx, 8
repe cmpsb       ; 8 bytes equal?
jnz different
```

Related: `scasb`, `repe`, `cmp`

## scasb, scasw, scasd – search memory (string)

Compares `al`/`ax`/`eax` with `[edi]` (like `cmp`) and moves `edi` on. With `repne` it searches until the value is found or `ecx` becomes 0.

**Flags:** as `cmp`

```asm
xor al, al       ; look for the 0
mov ecx, -1
repne scasb      ; find the text end
not ecx
dec ecx          ; ecx = length
```

Related: `cmpsb`, `repne`

## insb, insw, insd, outsb, outsw, outsd – port and memory (string)

`insb`/`insw`/`insd` read from the I/O port `dx` to `[edi]`, `outsb`/`outsw`/`outsd` write `[esi]` to the port `dx`; the pointer is moved on. With `rep` for whole blocks. Only for drivers and DOS: Windows programs may not access ports.

**Flags:** none

Related: `in`, `out`, `rep`

## rep, repe, repz – prefix: repeat

Repeats the following string instruction until `ecx` (16 bit: `cx`) is 0; after each round `ecx` is decreased by 1.

- before `movs`, `stos`, `lods`, `ins`, `outs`: exactly `ecx` times
- before `cmps`, `scas` (then called `repe`/`repz`): also only as long as ZF = 1 (equal)

`rep`, `repe` and `repz` are the same byte F3.

```asm
rep stosb      ; fill ecx bytes
```

Related: `repne`, `movsb`, `stosb`, `cmpsb`

## repne, repnz – prefix: repeat while not equal

Repeats `cmps` or `scas` as long as `ecx` is not 0 and the values are not equal (ZF = 0). Byte F2.

```asm
repne scasb      ; look for al
```

Related: `rep`, `scasb`

## lock – prefix: atomic

Makes the following instruction with a memory destination (e.g. `add`, `inc`, `xchg`, `cmpxchg`) atomic: no other processor can access this memory place in between. For counters and locks between threads.

```asm
lock inc dword [counter]
```

Related: `xchg`

## cs, ds, es, ss, fs, gs – prefix: segment

The memory operand of the following instruction applies in this segment instead of the usual one (mostly `ds`, `ss` for `esp`/`ebp`). Dismonite writes the prefix as a word of its own before the instruction, e.g. `cs lodsb`.

- 16-bit code (DOS): e.g. read data in the code segment (`cs`).
- Windows: `fs:[0]` is the start of the thread information block (TEB); `fs:[0x30]` points to the process (PEB).

```asm
mov eax, [fs:0x18] ; the TEB
```

Related: `mov`, `lodsb`, `les`

## xlatb – look up in a table

Replaces `al` by the byte at `[ebx + al]` (16 bit: `[bx + al]`): a lookup in a table of 256 bytes.

**Flags:** none

```asm
mov ebx, hex   ; '0123...ABCDEF'
and al, 0x0F
xlatb            ; al = digit
```

Related: `mov`, `lea`

## int, into – raise an interrupt

Calls the interrupt routine with the number: flags, `cs` and `ip` go on the stack, then execution continues at the address from the interrupt table; back with `iret`.

- DOS: `int 0x21` calls a DOS function (number in `ah`), `int 0x10` the video BIOS.
- Linux (32 bit): `int 0x80` calls the system (number in `eax`).
- `int3` (code CC) is the breakpoint of a debugger.
- `into`: interrupt 4 if OF = 1 (overflow).

Windows programs call functions from DLLs, no `int`.

**Flags:** IF and TF are cleared in the routine

```asm
mov ah, 0x09     ; print text
mov dx, text     ; up to '$'
int 0x21
```

Related: `iret`, `call`, `cli`

## iret, iretd – return from an interrupt

Takes `ip`, `cs` and the flags from the stack that `int` (or a hardware interrupt) put there. `iret` 16 bit, `iretd` 32 bit.

**Flags:** all from the stack

Related: `int`, `ret`, `retf`

## hlt – halt

Stops the processor until an interrupt comes. Only for the operating system; in Windows programs an exception.

**Flags:** none

Related: `cli`, `sti`, `int`

## in – read from a port

Reads a value from an I/O port into `al`, `ax` or `eax`. The port number is a number (0 to 255) or is in `dx`.

**Syntax:** `in al, port` or `in al, dx`

Only under DOS and in drivers; Windows programs may not do this.

**Flags:** none

```asm
in al, 0x60      ; keyboard code
```

Related: `out`, `insb`

## out – write to a port

Writes `al`, `ax` or `eax` to an I/O port (number or `dx`).

**Syntax:** `out port, al` or `out dx, al`

**Flags:** none

```asm
mov al, 0x20
out 0x20, al     ; EOI to the PIC
```

Related: `in`, `outsb`

## les, lds, lfs, lgs, lss – load a far pointer

Loads a pointer made of segment and offset (16 bit: 4 bytes; 32 bit: 6 bytes) from memory: the offset into the register, the segment into `es` (`les`), `ds` (`lds`), `fs`, `gs` or `ss`.

**Syntax:** `les dest, [address]`

Typical in 16-bit code (DOS, Turbo Pascal) to reach data in another segment.

**Flags:** none

```asm
les di, [pointer] ; es:di = pointer
mov al, [es:di]
```

Related: `mov`, segment prefixes (`es`, ...)

## bound – check an index

Checks whether a register lies between two limits in memory (lower limit, upper limit behind it). If it is outside, the processor raises interrupt 5. Rarely used.

**Syntax:** `bound register, [limits]`

**Flags:** none

Related: `cmp`, `int`

## aaa, aas, aam, aad, daa, das – BCD arithmetic

Correct the result of a calculation with decimal digits (BCD, one digit per 4 or 8 bits):

- `aaa`, `aas`: after `add`/`sub` with unpacked digits (one per byte)
- `daa`, `das`: after `add`/`sub` with packed digits (two per byte)
- `aam`: after `mul`: `ah = al / 10`, `al = al mod 10`
- `aad`: before `div`: `al = ah * 10 + al`, `ah = 0`

Hardly used today (they no longer exist in 64-bit mode).

**Flags:** AF and CF for the carry

```asm
mov al, 0x38     ; '8'
add al, 0x35     ; + '5'
aaa              ; ah:al = 1:3
```

Related: `add`, `sub`, `mul`, `div`

## wait – wait for the coprocessor

Waits until the floating-point coprocessor (x87) is finished and reports its pending errors. Often stands before x87 instructions.

**Flags:** none

Related: `fpu`

## fpu – floating-point instruction (x87)

An instruction for the floating-point coprocessor (codes D8 to DF): `fld`, `fstp`, `fadd`, `fmul`, ... Dismonite knows its length, but not yet its name; the assembler does not know the x87 instructions yet.

The x87 registers form a stack `st0` to `st7`; values are loaded with `fld` and stored with `fstp`.

Related: `wait`

## lgdt, lidt, sgdt, sidt – descriptor tables

Load (`lgdt`, `lidt`) or store (`sgdt`, `sidt`) address and size of the global descriptor table (GDT) or the interrupt table (IDT). The tables describe the segments and the interrupt routines in protected mode.

Only the operating system (ring 0) may load; `sgdt`/`sidt` are also allowed in programs.

**Flags:** none

Related: `lldt`, `ltr`, `lmsw`

## lldt, sldt, ltr, str – LDT and task register

- `lldt`/`sldt`: load the local descriptor table / read the selector
- `ltr`/`str`: load / read the task register (task state segment)

Loading only in the operating system (ring 0).

**Flags:** none

Related: `lgdt`, `lar`

## smsw, lmsw, clts – machine status

- `smsw`: read the machine status word (the lower 16 bits of CR0)
- `lmsw`: set it (e.g. the bit for protected mode)
- `clts`: clear the task-switched flag in CR0

`lmsw` and `clts` only in the operating system (ring 0).

**Flags:** none

Related: `lgdt`

## lar, lsl, verr, verw, arpl – check selectors

Protected-mode instructions that examine a segment selector:

- `lar`: read the access rights of the segment
- `lsl`: read its limit (size)
- `verr`, `verw`: is it readable / writable? (ZF = 1: yes)
- `arpl`: adjust the privilege level of a selector

**Flags:** ZF (result of the check)

Related: `lldt`, `lgdt`

## !label

**Label** (jump mark): a name for an address. Jumps, calls and data refer to it.

Dismonite gives automatic names like `C00401020` (a `call` points to it), `J00401020` (a jump) or `L00401020` (data only); with **N** you give a label a name of your own, Ctrl+click on a name (or the key **F** in the row) jumps there.
