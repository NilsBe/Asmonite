# ARM64 instructions (A64, ARMv8)

The instruction info of Dismonite and Asmonite (F1) for ARM64 (AArch64, `.arch arm64`): every instruction is 4 bytes long. There are 31 general registers: `x0` to `x30` with 64 bits, or the lower half as `w0` to `w30` with 32 bits. Writing to a `w` register clears the upper 32 bits. Register 31 is either `sp` (the stack) or `xzr`/`wzr` (always 0), depending on the instruction.

Each section starts with `## ` and the names it explains; long lists stand in a line `<!-- names: ... -->`. `b.eq` or `adds` are found under `b` or `add`.

## cond – conditions
<!-- names: eq, ne, cs, hs, cc, lo, mi, pl, vs, vc, hi, ls, ge, lt, gt, le, al, nv -->

A condition tests the flags N, Z, C and V. It stands behind the name with a point (`b.eq`) or as the last operand (`csel x0, x1, x2, ne`, `cset w0, lt`).

- `eq` equal (Z = 1), `ne` not equal (Z = 0)
- unsigned: `hs`/`cs` >=, `lo`/`cc` <, `hi` >, `ls` <=
- signed: `ge` >=, `lt` <, `gt` >, `le` <=
- `mi` negative (N = 1), `pl` not negative
- `vs` overflow (V = 1), `vc` no overflow
- `al` always

The flags are set by `cmp`, `cmn`, `tst`, `ccmp` or an instruction with `s` (`adds`, `subs`, `ands`, ...). Unlike ARM32, ordinary instructions are not conditional; only branches, `csel` and its relatives and `ccmp` are.

Related: `cmp`, `b`, `csel`

## xzr, wzr – zero register

Register 31 reads as 0 in most instructions and discards what is written to it. So `mov x0, xzr` clears `x0`, `cmp x1, #0` is really `subs xzr, x1, #0`, and `mul` is `madd` with `xzr`.

Where the instruction allows `sp` for register 31 (`add`, `sub` with an immediate, loads and stores as the base), the same number means the stack pointer instead.

Related: `sp`, `mov`, `cmp`

## sp, wsp – stack pointer

The stack pointer. It must be a multiple of 16 whenever it is used as the base of a load or store, otherwise the processor raises an alignment fault. The stack grows downwards.

Typical function entry and exit:

```asm
stp x29, x30, [sp, #-16]!   ; push frame pointer and return address
mov x29, sp
...
ldp x29, x30, [sp], #16     ; pop them
ret
```

Related: `stp`, `ldp`, `lr`

## lr, x30, fp, x29 – link register and frame pointer

- `x30` (`lr`): `bl` and `blr` store the return address here, `ret` jumps to it. A function that calls another one must save it first.
- `x29` (`fp`): the frame pointer, a chain to the callers' frames; used by debuggers for the call stack.

Calling convention (Windows and Linux): arguments in `x0` to `x7`, result in `x0`; `x0`-`x17` may be changed by the called function; `x19`-`x28` must be kept; `x18` is reserved by the system.

Related: `bl`, `ret`, `stp`

## x18 – platform register

On Windows ARM64 `x18` points to the thread information block (TEB) of the thread; it must not be used for anything else. The system also reserves it on other platforms.

Related: `lr`

## mov – copy a value
<!-- names: mov, movz, movk, movn -->

`mov` copies a register or a number. It is an alias: a register copy is `orr rd, xzr, rm`, a small number is `movz`, a negative one `movn`, and a bit pattern a logical `orr`. Between registers it also reaches `sp` (`mov sp, x0` is `add sp, x0, #0`).

- `movz rd, #imm16{, lsl #16|32|48}`: 16 bits at the given position, the rest 0
- `movk rd, #imm16, lsl #16`: replaces only those 16 bits, keeps the others
- `movn rd, #imm16`: the inverted value (`~imm16`)

Any 64-bit number is built with one `movz` and up to three `movk`.

**Flags:** none

```asm
mov x0, #0x1234
movz x1, #0xbeef
movk x1, #0xdead, lsl #16   ; x1 = 0xdeadbeef
mov x2, x1
```

Related: `mvn`, `orr`, `adr`

## mvn – invert
<!-- names: mvn, orn -->

`mvn rd, rm` is `orn rd, xzr, rm`: `rd = ~rm`. `orn rd, rn, rm` is `rd = rn | ~rm`.

**Flags:** none

Related: `mov`, `orr`

## adr, adrp – address relative to pc

- `adr rd, label`: `rd` = the address of a label within +-1 MB
- `adrp rd, label`: `rd` = the address of the 4 KB page of the label (the low 12 bits are 0), range +-4 GB; the low part is then added with `add rd, rd, :lo12:label` or a `ldr`'s offset

`adrp` is how code reaches data in a position-independent program.

**Flags:** none

```asm
adr x0, text        ; address of text
adrp x1, data
add x1, x1, #0x10   ; page + offset in page
```

Related: `add`, `ldr`

## add, adds – add
<!-- names: add, adds, cmn -->

Adds two values: `rd = rn + operand`. The operand is a register (optionally shifted: `lsl #n`, or extended: `uxtw`, `sxtw`, ...) or a 12-bit number (optionally `lsl #12`). `adds` also sets the flags; `cmn rn, op` is `adds xzr, rn, op` (only the flags).

**Syntax:** `add rd, rn, rm{, shift}` or `add rd, rn, #imm`

**Flags:** `adds`, `cmn`: N, Z, C, V

```asm
add x0, x1, x2
add w3, w3, #1
add x4, x5, x6, lsl #3   ; x5 + 8*x6
```

Related: `sub`, `adc`, `cmp`

## sub, subs – subtract
<!-- names: sub, subs, cmp, neg, negs -->

`rd = rn - operand`, operands as with `add`. `subs` sets the flags; `cmp rn, op` is `subs xzr, rn, op`, `neg rd, rm` is `sub rd, xzr, rm`.

**Syntax:** `sub rd, rn, rm{, shift}` or `sub rd, rn, #imm`

**Flags:** `subs`, `cmp`, `negs`: N, Z, C, V

```asm
sub sp, sp, #32      ; room on the stack
subs x0, x0, #1      ; count down, Z when 0
cmp x1, #10
```

Related: `add`, `cmp`, `sbc`

## adc, adcs, sbc, sbcs, ngc, ngcs – with carry

`adc rd, rn, rm` is `rn + rm + C`; `sbc` is `rn - rm - (1 - C)`; `ngc` is `sbc` from zero. With `adds`/`subs` they add numbers wider than 64 bits.

**Flags:** the `s` forms: N, Z, C, V

```asm
adds x0, x0, x2   ; low half
adc  x1, x1, x3   ; high half
```

Related: `add`, `sub`

## and, ands, tst – and
<!-- names: and, ands, tst -->

Bitwise and. The operand is a register (optionally shifted) or a bit pattern: a run of 1 bits, rotated and repeated (the encoder knows which numbers are possible). `ands` sets N and Z (C and V become 0); `tst rn, op` is `ands xzr, rn, op`.

**Flags:** `ands`, `tst`: N, Z

```asm
and x0, x0, #0xff    ; keep the low byte
tst w1, #1           ; is bit 0 set?
b.ne odd
```

Related: `orr`, `eor`, `bic`

## orr, eor, eon – or, exclusive or

- `orr rd, rn, op`: or
- `eor rd, rn, op`: exclusive or (`eor x0, x0, x0` clears; `mov` with a bit pattern is `orr`)
- `eon rd, rn, rm`: `rn ^ ~rm`

**Flags:** none

Related: `and`, `mov`

## bic, bics – clear bits

`bic rd, rn, rm` is `rn & ~rm`; `bics` also sets N and Z.

**Flags:** `bics`: N, Z

Related: `and`, `orr`

## lsl, lsr, asr, ror – shift and rotate

- `lsl rd, rn, #n|rm`: left, fills with 0
- `lsr`: right, fills with 0 (unsigned)
- `asr`: right, copies the sign bit (signed)
- `ror`: rotate right

These are aliases: with an immediate, `lsl`/`lsr`/`asr` are `ubfm`/`sbfm`, `ror` is `extr`; with a register they are `lslv`, `lsrv`, `asrv`, `rorv`.

**Flags:** none

```asm
lsl x0, x1, #3      ; x0 = x1 * 8
asr w2, w2, #31     ; all ones if negative
```

Related: `ubfm`, `extr`

## mul, madd, msub, mneg – multiply
<!-- names: mul, madd, msub, mneg -->

- `madd rd, rn, rm, ra`: `rd = ra + rn * rm`
- `msub rd, rn, rm, ra`: `rd = ra - rn * rm`
- `mul rd, rn, rm` is `madd rd, rn, rm, xzr`; `mneg` is `msub` with `xzr`

The result has the register's width (the low half of the product). The remainder of a division is `msub` of quotient times divisor.

**Flags:** none

```asm
sdiv x2, x0, x1
msub x3, x2, x1, x0   ; x3 = x0 % x1
```

Related: `smull`, `sdiv`

## smull, umull, smaddl, umaddl, smsubl, umsubl, smulh, umulh – long multiply

- `smull xd, wn, wm`: signed 32 x 32 -> 64 bits (`smaddl` with `xzr`)
- `umull xd, wn, wm`: the same unsigned
- `smaddl`/`umaddl`/`smsubl`/`umsubl`: with accumulate or subtract
- `smulh`/`umulh xd, xn, xm`: the upper 64 bits of the 128-bit product

**Flags:** none

Related: `mul`

## sdiv, udiv – divide

`sdiv`: signed, `udiv`: unsigned; `rd = rn / rm`, rounded towards 0. Division by 0 gives 0 (no exception). There is no remainder instruction: use `msub`.

**Flags:** none

Related: `mul`, `msub`

## ubfm, sbfm, bfm, ubfx, sbfx, ubfiz, sbfiz, bfi, bfxil, bfc – bit fields
<!-- names: ubfm, sbfm, bfm, ubfx, sbfx, ubfiz, sbfiz, bfi, bfxil, bfc -->

One family of instructions moves bit fields; the common cases have names:

- `ubfx rd, rn, #lsb, #width`: take a field out, zero-extended
- `sbfx`: the same, sign-extended
- `ubfiz rd, rn, #lsb, #width`: put the low bits at `lsb`, rest 0
- `bfi rd, rn, #lsb, #width`: insert the low bits into `rd`, keep the others
- `bfxil`: take a field and insert it at the bottom of `rd`
- `bfc rd, #lsb, #width`: clear a field
- `lsl`, `lsr`, `asr`, `sxtb`, `uxth`, ... are special cases of `ubfm`/`sbfm`

**Flags:** none

```asm
ubfx x0, x1, #8, #4    ; bits 11..8 of x1
bfi  w2, w3, #4, #8
```

Related: `lsl`, `sxtb`, `extr`

## extr – extract from a pair

`extr rd, rn, rm, #lsb`: takes 64 (32) bits out of the 128 (64) bits `rn:rm` starting at bit `lsb`. With `rn = rm` it is a rotate (`ror`).

**Flags:** none

Related: `ror`, `ubfm`

## sxtb, sxth, sxtw, uxtb, uxth – extend

Widen the lower 8, 16 or 32 bits of a register: `sxt*` with the sign, `uxt*` with zeros. They are aliases of `sbfm`/`ubfm` (`uxtw` is a `mov` of the `w` register).

**Flags:** none

```asm
sxtw x0, w0       ; int -> long
uxtb w1, w1
```

Related: `ubfm`, `ldrsw`

## clz, cls, rbit, rev, rev16, rev32 – count and reverse

- `clz`: number of leading zero bits (64 for 0)
- `cls`: leading bits equal to the sign bit
- `rbit`: reverse the bit order
- `rev`: reverse the byte order (endianness); `rev16`: the bytes in each halfword; `rev32`: in each word

**Flags:** none

Related: `lsl`

## csel, csinc, csinv, csneg, cset, csetm, cinc, cinv, cneg – conditional select
<!-- names: csel, csinc, csinv, csneg, cset, csetm, cinc, cinv, cneg -->

Select one of two values by a condition; no branch is needed.

- `csel rd, rn, rm, cond`: `rd = cond ? rn : rm`
- `csinc`/`csinv`/`csneg`: the second value is `rm + 1`, `~rm` or `-rm`
- `cset rd, cond`: 1 if true, else 0; `csetm`: all ones if true
- `cinc`/`cinv`/`cneg rd, rn, cond`: `rn` changed if the condition is true

**Flags:** none

```asm
cmp x0, x1
csel x2, x0, x1, gt    ; x2 = max(x0, x1)
cset w3, eq            ; w3 = (x0 == x1)
```

Related: `cond`, `cmp`, `ccmp`

## ccmp, ccmn – conditional compare

`ccmp rn, rm|#imm, #nzcv, cond`: if the condition is true, compare as `cmp`; else set the flags to `nzcv`. So several conditions are chained without branches (`a < b && c < d`).

**Flags:** N, Z, C, V

Related: `cmp`, `csel`, `cond`

## ldr, str – load and store
<!-- names: ldr, str -->

`ldr rt, [address]` loads a register (`w`: 4 bytes, `x`: 8 bytes, also `s`/`d`/`q` of the FP registers), `str` stores it. Addressing:

- `[xn]`, `[xn, #off]`: base and offset (a multiple of the size, or the unscaled `ldur`/`stur` with -256..255)
- `[xn, #off]!`: change `xn` first (pre-index)
- `[xn], #off`: use `xn`, then change it (post-index)
- `[xn, xm{, lsl #n}]`, `[xn, wm, sxtw]`: base plus register
- `ldr rt, label`: a constant behind the code, relative to pc (within +-1 MB)

Only these instructions access memory; everything else works on registers.

**Flags:** none

```asm
ldr x0, [x1]
ldr w2, [x1, #8]
str x3, [sp, #-16]!   ; push
ldr x4, [x5, x6, lsl #3]
```

Related: `ldp`, `ldrb`, `ldur`, `adrp`

## ldrb, strb, ldrh, strh – byte and halfword

`ldrb`/`ldrh` load 1 or 2 bytes and fill the register with zeros, `strb`/`strh` store the low byte or halfword. Addressing as with `ldr`.

**Flags:** none

Related: `ldr`, `ldrsb`

## ldrsb, ldrsh, ldrsw – load with sign

Load 1, 2 or 4 bytes and extend with the sign bit into a `w` or `x` register (`ldrsw` only to `x`).

**Flags:** none

```asm
ldrsw x0, [x1]     ; int -> long
```

Related: `ldrb`, `sxtw`

## ldur, stur, ldurb, sturb, ldurh, sturh – unscaled offset

Like `ldr`/`str`, but the offset is any number from -256 to 255 (not a multiple of the size). The assembler picks `ldur` by itself when the offset of `ldr` does not fit.

**Flags:** none

Related: `ldr`

## ldp, stp, ldpsw – two registers
<!-- names: ldp, stp, ldpsw -->

Load or store two registers with consecutive addresses in one instruction. The offset is a multiple of the size (-512..504 for `x`), pre- and post-index work as with `ldr`. The most common use is saving and restoring `x29` and `x30`.

**Flags:** none

```asm
stp x29, x30, [sp, #-32]!
stp x19, x20, [sp, #16]
...
ldp x19, x20, [sp, #16]
ldp x29, x30, [sp], #32
```

Related: `ldr`, `sp`, `lr`

## ldxr, stxr, ldaxr, stlxr, ldar, stlr – exclusive and acquire/release
<!-- names: ldxr, stxr, ldaxr, stlxr, ldar, stlr, ldxp, stxp, clrex -->

Atomic read-modify-write by two instructions: `ldxr` reads and marks the address, `stxr ws, rt, [xn]` stores only if nothing else wrote there meanwhile (`ws` = 0 on success, 1 on failure; then repeat). `a` (acquire) and `l` (release) in the names order the memory accesses for other processors. `clrex` clears the mark.

**Flags:** none

```asm
retry:
ldaxr w1, [x0]
add w1, w1, #1
stlxr w2, w1, [x0]
cbnz w2, retry
```

Related: `ldadd`, `dmb`

## ldadd, ldclr, ldeor, ldset, swp, cas – atomic operations
<!-- names: ldadd, ldclr, ldeor, ldset, ldsmax, ldsmin, ldumax, ldumin, swp, cas, casp -->

Single instructions (ARMv8.1) that read memory, change it atomically and return the old value in `rt`: `ldadd rs, rt, [xn]` adds `rs`, `ldclr` clears bits, `ldeor`, `ldset`, `ldsmax`..., `swp` exchanges, `cas` compares and swaps. The variants `a`, `l`, `al` and the sizes `b`, `h` follow the names (`ldaddal`, `casb`).

**Flags:** none

Related: `ldxr`, `dmb`

## prfm, prfum – prefetch

Tells the processor that an address will be needed soon (`prfm pldl1keep, [x0, #64]`). It never changes the result of the program.

**Flags:** none

Related: `ldr`

## b – jump, b.cond – conditional jump
<!-- names: b, b.eq, b.ne, b.cs, b.cc, b.mi, b.pl, b.hi, b.ls, b.ge, b.lt, b.gt, b.le -->

`b label` jumps within +-128 MB. `b.cond label` jumps only if the condition is true (+-1 MB), else the next instruction runs; the condition is the one of the last instruction that set the flags.

**Flags:** none

```asm
cmp x0, #10
b.lt small
b done
```

Related: `cond`, `cbz`, `bl`

## bl – call
<!-- names: bl, blr -->

`bl label` stores the address of the next instruction in `x30` (`lr`) and jumps there; `blr xn` does the same for an address in a register (pointers, imports). The function returns with `ret`. Because `lr` is overwritten, a function that calls others must save it (see `stp`).

**Flags:** none

```asm
bl memcpy
adrp x16, __imp_MessageBoxA
ldr x16, [x16]
blr x16
```

Related: `ret`, `lr`, `br`

## br – jump to a register

`br xn` jumps to the address in `xn` (jump tables, tail calls, import thunks).

**Flags:** none

Related: `blr`, `ret`

## ret – return

`ret` jumps to the address in `x30` (`ret xn` to another register). The processor predicts it from the earlier `bl`.

**Flags:** none

Related: `bl`, `lr`

## cbz, cbnz – compare with 0 and jump

`cbz rt, label` jumps if the register is 0, `cbnz` if it is not; range +-1 MB. Flags are not changed.

**Flags:** none

```asm
cbz x0, failed
```

Related: `tbz`, `b`

## tbz, tbnz – test a bit and jump

`tbz rt, #bit, label` jumps if the bit is 0, `tbnz` if it is 1; range +-32 KB. Flags are not changed.

**Flags:** none

```asm
tbnz w0, #31, negative
```

Related: `cbz`, `tst`

## svc, hvc, smc – system call

`svc #n` calls the operating system. On Linux the number is in `x8` and the arguments in `x0`...; Windows programs use the DLLs instead and `svc` only in system code.

**Flags:** none

Related: `brk`

## brk, hlt, udf – breakpoint and undefined

- `brk #n`: a breakpoint; the debugger stops here (Windows: `brk #0xf000` is a debug break)
- `hlt #n`: halt for an external debugger
- `udf #n`: a defined "undefined instruction" (always an exception)

**Flags:** none

Related: `svc`

## nop, yield, wfe, wfi, sev, sevl – hints
<!-- names: nop, yield, wfe, wfi, sev, sevl, hint, csdb, esb, psb -->

Instructions that change nothing of the program: `nop` does nothing (padding), `yield` tells that a spin loop waits, `wfe`/`wfi` wait for an event or an interrupt, `sev` sends one. Unknown hints (`hint #n`) are ignored by processors that do not know them.

**Flags:** none

Related: `dmb`

## dmb, dsb, isb – barriers

- `dmb`: memory accesses before it are seen before those after it (by other processors)
- `dsb`: waits until all earlier memory accesses are done
- `isb`: discards prefetched instructions (after changing code or system registers)

The operand (`ish`, `sy`, `ishld`, ...) selects the domain and kind.

**Flags:** none

Related: `ldar`, `ldxr`

## mrs, msr – system registers

`mrs xt, sysreg` reads, `msr sysreg, xt` writes a system register (`nzcv`, `tpidr_el0`, `cntvct_el0`, `fpcr`, ...). Programs use few of them; `tpidr_el0` is the thread pointer on Linux, `cntvct_el0` the counter.

**Flags:** `msr nzcv`: N, Z, C, V

Related: `dmb`

## paciasp, autiasp, pacia, autia, xpaclri, bti – pointer authentication
<!-- names: paciasp, pacibsp, autiasp, autibsp, pacia, pacib, autia, autib, pacga, xpaclri, xpaci, xpacd, retaa, retab, braa, blraa, bti -->

Security extensions: `paciasp` signs `lr` with a key and `sp`, `autiasp` checks it before `ret` (a changed return address then crashes); `retaa` is `autiasp` and `ret` together. `bti` marks a place where an indirect jump may land. On older processors they work as `nop`.

**Flags:** none

Related: `ret`, `nop`

## fmov – copy a floating-point value

Copies between FP registers (`s0`, `d0`) or between a general and an FP register, or loads a small constant (`fmov d0, #1.0`).

**Flags:** none

```asm
fmov d0, #2.0
fmov x1, d0     ; the bits
fmov s1, w2
```

Related: `fadd`, `scvtf`

## fadd, fsub, fmul, fdiv, fneg, fabs, fsqrt – floating-point arithmetic
<!-- names: fadd, fsub, fmul, fdiv, fneg, fabs, fsqrt, fmax, fmin, fmadd, fmsub, fnmadd, fnmsub -->

Single precision (`s0`..`s31`) or double precision (`d0`..`d31`), rounded as the control register `fpcr` says. `fmadd rd, rn, rm, ra` is `ra + rn * rm`. The same registers are the NEON registers `v0`..`v31`.

**Flags:** none

```asm
fmul d0, d1, d2
fsqrt d3, d0
```

Related: `fcmp`, `fcvt`

## fcmp, fcmpe, fccmp, fcsel – floating-point compare

`fcmp dn, dm` sets N, Z, C, V as for integers; with an unordered operand (a NaN) the flags are `0011`, so `b.vs` tests it. `fcsel` selects by a condition.

**Flags:** N, Z, C, V

Related: `cond`, `fadd`

## fcvt, fcvtzs, fcvtzu, scvtf, ucvtf – convert

- `scvtf dd, xn` / `ucvtf`: integer -> floating-point
- `fcvtzs xd, dn` / `fcvtzu`: floating-point -> integer, rounded towards 0
- `fcvtas`, `fcvtns`, `fcvtms`, `fcvtps`: other rounding
- `fcvt dd, sn`: between single and double precision

**Flags:** none

```asm
scvtf d0, x0
fcvtzs w1, s2
```

Related: `fmov`

## ld1, st1, dup, movi – NEON vectors
<!-- names: ld1, ld2, ld3, ld4, st1, st2, st3, st4, dup, movi, ins, umov, smov, addv, addp, cnt, zip1, zip2, uzp1, uzp2, ext, tbl, bsl, bif, bit, cmeq, cmgt, cmhi -->

The registers `v0`..`v31` hold 128 bits and are used as 16 bytes, 8 halfwords, 4 words or 2 doublewords (`v0.16b`, `v0.4s`, `v0.2d`); `d0`, `s0` are their lower parts. NEON instructions work on all lanes at once. `ld1`/`st1` load and store lanes, `dup` copies a value into all lanes, `movi` loads a constant, `add v0.4s, v1.4s, v2.4s` adds four words.

**Flags:** none

Related: `fadd`, `ldr`
